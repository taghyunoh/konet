# konet 기능 변경 내역서

- **작업일**: 2026-07-18
- **대상**: konet_web (물류/재고/상품 관리)

## 1. 변경 요약

| 화면 | 변경 내용 | 반영 조건 |
|---|---|---|
| 견적서관리 ▸ 매출 엑셀 업로드 | 조회 줄에 품목코드/품목명 검색란 추가 (부분일치) | 서버 재시작 필요 |
| 재고현황 ▸ 수불 내역 | 출고 자동연동 행에 사업장 표시 + 여러 곳이면 접기/펼치기 | 서버 재시작 필요 |
| 상품(품목)관리 ▸ 이력/재고 | 매출단가(조회) 탭 신설 — 매출 확정내역 단가 조회 전용 | 즉시 반영됨 |

## 2. 매출 확정내역 조회 — 품목코드/품목명 검색

- 조회 줄이 `[납품일자(시작)] [납품일자(종료)] [출고장] [품목코드/품목명] [조회]` 구성으로 확장.
- **부분일치 검색**: 예) `736038` 또는 `덮밥용기` 만 입력해도 해당 행을 찾음. 비우면 전체 조회.
- 품목코드와 품목명을 한 칸에서 함께 검색 (OR 조건).
- 변경 파일: `logistics_demo2.jsp` (검색란·파라미터), `User_SQL.xml`의 `selectSalesMst` (ITEM_CD·ITEM_NM LIKE 조건)

## 3. 재고현황 수불 내역 — 사업장 표시

### 3.1 배경

출고 자동연동(SHIPOUT) 행은 여러 사업장의 출고를 품목·일자 단위로 합산해 수불원장에 기록하므로 사업장 칸(BIZ_CD)이 비어 있었음.

### 3.2 변경

- SHIPOUT 행은 출고 원본(`TBL_SHIPOUT_MST`)에서 **같은 품목·출고일자의 사업장명**을 찾아 표시 (수량이 있는 활성 출고분 기준).
- 사업장이 여러 곳이면 화면에는 **첫 사업장 + `＋N`** 만 표시. `＋N` 클릭 시 전체 목록 펼침, `－` 클릭 시 접힘.
- 수기 입고 등 SHIPOUT이 아닌 행은 기존처럼 원장의 사업장 값을 그대로 표시.
- 변경 파일: `User_SQL.xml`의 `selectStockLedgerList` (사업장 연계), `logistics_demo2.jsp` (＋N 펼침 UI)

## 4. 상품(품목)관리 — 매출단가(조회) 탭 신설

### 4.1 방침

- **판매가 탭은 직접 입력(자체 입력) 이력 전용**으로 유지. 매출 확정내역(`TBL_SALES_MST`)을 판매가 이력에 섞지 않음.
- 대신 매출 확정내역의 실제 판매단가는 **별도 탭에서 조회 전용**으로 표시.

### 4.2 새 탭 구성

- 이력/재고 패널 탭: **매입가 · 판매가 · 매출단가(조회) · 재고(수불)** 4개.
- 매출단가(조회) 탭 표시 항목: 납품일자 · 출고장 · 발주번호 · 판매단가 · 출고량 · 매출액 · 원본파일.
- 상단 요약: 총 행수 · 단가 종수 · 출고량 합 · 매출액 합.
- 조회 전용 탭이므로 입력·삭제 버튼 없음. 원본 관리는 **견적서관리 ▸ 매출 엑셀 업로드**에서.
- 변경 파일: `prodmst.jsp` (탭·조회 함수 추가, 서버 코드 변경 없음)

## 5. 이력/재고 탭별 데이터 출처

| 탭 | 테이블 | 비고 |
|---|---|---|
| 매입가 | TBL_PROD_INPRICE_HST | 등록 시 상품마스터 IN_PRICE 동기화 |
| 판매가 | TBL_PROD_SALEPRICE_HST | 직접 입력 + 매출 엑셀 저장 시 자동 반영분. 기준매입은 저장 시점 마스터 입고가의 사본 |
| 매출단가(조회) | TBL_SALES_MST | 발주서(매출 엑셀) 업로드분. 조회 전용 |
| 재고(수불) | TBL_STOCK_LEDGER (+ TBL_STOCK_MST 요약) | 출고분은 TBL_SHIPOUT_MST에서 자동연동(REF_GB='SHIPOUT') |

## 6. 매출 엑셀 저장 → 판매단가 이력 자동 반영 흐름 (참고)

매출 엑셀 저장(`/sales/saveSalesMst.do`) 한 번에 두 테이블이 순서대로 처리된다.

1. **(A) TBL_SALES_MST 적재** — 배치(납품일자+출고장) 단위로 기존 자료를 이력마감(`ACTION_YN='N'`)한 뒤 행 INSERT.
2. **(B) TBL_PROD_SALEPRICE_HST 자동 반영** (`mergeSalepriceFromSales`) — 저장한 행들을 품목코드+납품일자로 묶어 upsert.
   - 적용일(APPLY_DT) = **납품일자(DLV_DT = 발주일자)**. 출고일자 아님 — 먼 지역은 하루 당겨 출고하므로 매출마감(`APPLY_DT <= 발주일자`)과 기준을 맞추기 위함.
   - 기준매입(BASE_INPRICE) = 저장 시점 상품마스터 입고가의 사본. 비고 = "매출 엑셀 업로드 반영".

**반영 제외 조건** (저장 완료 토스트의 `이력 N종 반영 · 변화없음 N종 · 단가충돌 N종 제외`가 이 결과):

| 경우 | 처리 |
|---|---|
| 같은 품목·같은 날인데 단가가 서로 다름 | 건너뜀(skip) — 추측 금지 원칙 |
| 품목코드가 상품마스터(TBL_PROD_MST)에 없음 | 반영 안 됨(none) |
| 이미 같은 단가로 이력 존재 | 변화 없음(none) |
| 이력 반영 자체가 실패 | 매출 저장은 유지, 로그만 남김 (별도 try 분리) |

→ 발주서를 올렸는데 판매가 탭에 안 보이는 날짜는 대부분 **단가충돌 skip** 또는 **자동반영 기능 도입 이전 업로드분**이며, 매출단가(조회) 탭에서 원본으로 확인 가능. 상품관리 판매가 탭의 `+ 추가`(직접 입력, `insertSaleprice`)는 이와 별개의 등록 경로다.

## 7. 반영(배포) 안내

- **JSP 변경분**(검색란 UI, ＋N 펼침, 매출단가 탭): 배포 폴더(tmp4 wtpwebapps)에 복사 완료 — 브라우저 **새로고침만으로 반영**.
- **매퍼(User_SQL.xml) 변경분**(품목코드/품목명 서버 검색, 수불 내역 사업장 연계): **Eclipse에서 서버 재시작 후 반영**.
- 매출단가(조회) 탭은 서버 재시작 전에도 동작하도록 화면에서 품목 필터를 한 번 더 적용해 둠.
