> 진단·폴더·복구모델·프로시저·스케줄·**수동 백업**·점검·복원을 **파일 하나**에 순서대로 모아 두었습니다.
> 단계마다 `[완료] / [남음] / [필요할 때]` 표시가 있어, 필요한 블록만 드래그해서 F5 하면 됩니다.

- **스케줄 방식**: **SQL Server Agent** (Standard이므로 사용 가능 → 4단계는 '가'만 하면 됩니다)

## 순서

### 1단계 — 진단 (먼저 이것부터)

SSMS에서 [`00_진단_현재상태확인.sql`](00_진단_현재상태확인.sql) 실행. 여섯 개 결과 중 **아래 셋**이 이후를 결정합니다.

| 확인할 것 | 왜 |
|---|---|
| ~~에디션~~ | ✅ **Standard 확인 완료** — Agent 방식으로 확정 |
| **복구모델** | `FULL` 인데 로그백업을 안 하면 `.ldf` 가 무한정 커진다 (아래 ① 참고) |
| **DB 크기** | 백업 폴더 여유 공간을 정하는 근거 |
| **마지막 전체백업** | 비어 있으면 지금까지 백업이 한 번도 안 돈 것 |

> 개체 탐색기에 **`SQL Server 에이전트(에이전트 XPs 사용 안 함)`** 로 보이는 것은 **Agent 서비스가 멈춰 있다**는 뜻입니다(Standard이므로 Agent 자체는 있습니다). 4단계에서 서비스를 시작하면 `Agent XPs` 는 자동으로 켜집니다 — `sp_configure` 로 직접 켜지 마세요. 서비스 없이 옵션만 켜면 작업이 등록만 되고 실행되지 않습니다.

### 2단계 — 백업 폴더 만들기 ✅ *(2026-08-03 완료)*

이 서버는 **C 드라이브 하나뿐**(여유 약 131GB)이라 `C:\SQLBackup\` 에 두었습니다.

**RDP 없이 SSMS에서 만들 수 있습니다** — SQL Server가 직접 만들므로 폴더 권한을 따로 줄 필요도 없습니다.

```sql
EXEC master.dbo.xp_create_subdir N'C:\SQLBackup';
```

> `Program Files` 안(기본 백업 경로)이 아닌 별도 폴더에 둡니다 — 패치·재설치에 안 휘말리고, 외부 복사 대상으로 잡기도 쉽습니다.
>
> SQL Server가 만들지 않은 폴더를 쓴다면 서비스 계정(`NT SERVICE\MSSQLSERVER`)에 **수정** 권한이 필요합니다. 없으면 "액세스가 거부되었습니다"로 실패합니다.

### 2.5단계 — 복구모델 변경 (진단 결과에 따라)

이 DB는 **복구모델 `전체(FULL)` + 백업 이력 없음 + 로그(122.9MB) > 데이터(97.1MB)** 였습니다. 하루 1회 전체 백업만 할 것이므로 `단순(SIMPLE)` 로 바꿉니다.

```sql
ALTER DATABASE KOLGSDB SET RECOVERY SIMPLE;
USE KOLGSDB;
DBCC SHRINKFILE (N'KOLGSDB_log', 64);
```

### 3단계 — 백업 프로시저 설치

[`01_백업_프로시저.sql`](01_백업_프로시저.sql) 통째로 실행. 그다음 파일 맨 아래 주석을 풀어 **수동으로 한 번 실행**해서 성공하는지 확인합니다.

```sql
EXEC dbo.SP_BACKUP_FULL @BackupDir = N'C:\SQLBackup\', @KeepDays = 14;
SELECT TOP 5 * FROM dbo.TBL_BACKUP_LOG ORDER BY SEQ DESC;
```

프로시저가 하는 일: 전체 백업(압축·CHECKSUM) → **검증**(RESTORE VERIFYONLY) → 14일 지난 파일 삭제 → 결과 기록.

### 4단계 — 스케줄 걸기 (이 서버는 '가'만 하면 됩니다)

**가. SQL Agent** ✅ *Standard 확인됨*

**(1) 먼저 Agent 서비스를 켭니다** — RDP로 서버에 들어가서
- `services.msc` → **SQL Server Agent (MSSQLSERVER)** → 오른쪽 클릭 → **속성**
- **시작 유형: 자동** 으로 바꾸고 → **시작**
- SSMS 개체 탐색기를 새로 고치면 `(에이전트 XPs 사용 안 함)` 표시가 사라집니다

**(2)** [`02_스케줄_SQLAgent.sql`](02_스케줄_SQLAgent.sql) 실행 → 매일 **00:00(자정)** 작업 등록

**(3)** 파일 아래 주석을 풀어 **즉시 한 번 실행**해서 성공을 확인
```sql
EXEC msdb.dbo.sp_start_job @job_name = N'KOLGSDB 일일 전체백업';
```

**나. (해당 없음) Express용** — [`03_...bat`](03_스케줄_작업스케줄러_Express용.bat) 는 이 서버에선 쓰지 않습니다. 다른 Express 서버에 같은 백업을 걸 때를 위해 남겨 둡니다.

### 5단계 — 복원 연습 (한 번은 꼭)

[`04_복원_런북.sql`](04_복원_런북.sql) 의 3번으로 **다른 이름(`KOLGSDB_CHK`)에 복원**해 보고 자료를 확인한 뒤 지웁니다. 한 번도 복원해 보지 않은 백업은 정작 필요할 때 안 열리는 경우가 많습니다.

## 짚어둘 것 3가지

### ① 복구모델이 FULL이면 로그가 계속 큽니다

하루 1회 전체 백업만 할 계획이면 **SIMPLE** 이 맞습니다. 00번 3번 쿼리에서 `복구모델 = FULL` 이고 `마지막 로그백업` 이 비어 있다면 `.ldf` 가 데이터파일보다 클 겁니다.

```sql
ALTER DATABASE KOLGSDB SET RECOVERY SIMPLE;
DBCC SHRINKFILE (N'KOLGSDB_log', 1024);   -- 논리파일명은 00번 3번 결과에서 확인
```

**단, 이렇게 하면 "장애 직전 시점 복구"는 포기하는 것**입니다. 마지막 백업 이후 자료는 사라집니다. 하루치 손실을 감수하기로 하셨으니 SIMPLE이 맞지만, 나중에 "몇 시간 전으로 되돌려달라"는 요구가 생기면 이 결정부터 다시 봐야 합니다.

### ② 백업 파일이 같은 서버에만 있으면 반쪽입니다

디스크가 죽거나 서버가 통째로 문제가 되면 백업도 같이 사라집니다. `C:\SQLBackup\` 을 **NAS·다른 PC·클라우드로 주기 복사**해 두시길 권합니다. 필요하시면 로보카피 배치를 만들어 드리겠습니다.

### ③ 이 서버에는 다른 DB도 있습니다

`MESSENGER · ReportServer · SPORTS · SRCMAIN · SUNWOO` 가 함께 있습니다. 이번 설정은 **KOLGSDB만** 대상입니다. 다른 DB도 필요하면 `SP_BACKUP_FULL @DbName` 만 바꿔 호출하면 됩니다.

> 참고: SQL Server 2012 Standard는 마이크로소프트 지원이 끝난 버전입니다(연장 지원 2022-07 종료). 백업과는 별개 문제지만, 보안 갱신이 없다는 점은 알고 계시는 게 좋습니다.
>
> 백업 **압축**은 2012 Standard에서 지원됩니다 — `SP_BACKUP_FULL` 이 자동으로 켜므로 별도 설정은 필요 없습니다.

## 진행 이력

| 날짜 | 내용 |
|---|---|
| 2026-08-03 | 진단 — Standard 2012 / 복구모델 `전체` / **백업 이력 없음** / 데이터 97.1MB · 로그 122.9MB / C 드라이브 단독(여유 131GB) / 복제 미사용 |
| 2026-08-03 | `C:\SQLBackup` 생성 + **첫 수동 전체백업 성공** (12,397페이지 · 0.697초 · 검증 통과) |
| 2026-08-03 | 복구모델 `전체` → **`단순`** 변경, 로그 축소 **122.9MB → 64.6MB** |
| 2026-08-03 | `SP_BACKUP_FULL` 설치 + 실행 성공 — **15.2MB · 1초** (압축 정상 동작) |
| 2026-08-03 | ⚠️ **Agent 서비스 시작 실패** — `xp_cmdshell` 경유 `sc/net start` 가 `Access is denied`(오류 5). SQL Server 서비스 계정에 **다른 서비스를 제어할 권한이 없음**. `xp_cmdshell` 은 즉시 0으로 원복함. → **RDP `services.msc` 로만 가능** |

### 남은 일 (다음에 이어서)

1. **RDP** → `services.msc` → `SQL Server Agent (MSSQLSERVER)` → 시작 유형 **자동** → **시작**
2. SSMS 에서 [`02_스케줄_SQLAgent.sql`](02_스케줄_SQLAgent.sql) 실행 → **매일 00:00** 등록
3. `EXEC msdb.dbo.sp_start_job @job_name = N'KOLGSDB 일일 전체백업';` 로 즉시 한 번 확인

그때까지는 자동 백업이 없으므로, 필요할 때 수동으로:
```sql
EXEC master.dbo.SP_BACKUP_FULL @BackupDir = N'C:\SQLBackup\', @KeepDays = 14;
```
> `@BackupDir` 끝의 **역슬래시(`\`)를 빼먹지 말 것** — 폴더명과 파일명이 붙어 엉뚱한 경로가 된다.

> **`xp_cmdshell` 로 서비스를 켜려는 시도는 다시 하지 말 것** — 이 서버에서는 권한이 없어 실패하며, 보안 기능만 잠깐 열렸다 닫힌다. RDP 가 유일한 방법이다.
