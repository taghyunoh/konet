# 출고 원천 규칙 — 납기일자 기준 · 정산서 우선 (2026-09-03 확정)

## 규칙 한 줄
**납기일자(DLV_DT) 기준으로, 그 날 정산서가 있으면 발주현황표를 읽지 않고 정산서를 읽는다.**
정산서는 열흘쯤 늦게 오므로 그동안은 발주현황표(라벨수량)로 출고를 떨고, 정산서가 오면 그 날짜만 정산서로 갈아끼운다.

## 어디에 적용되나
| 화면 | 원천 | 구현 |
|---|---|---|
| 품목별재고현황 · 수불내역 · 재고마감 · 재고 일괄조정 | 수불원장 `TBL_STOCK_LEDGER` | `insertShipoutLedger`(발주행, 정산서 있는 날은 NOT EXISTS 로 제외) + `insertSalesLedger`(정산행). 정산서 업로드 = `syncSalesLedgerCore` 가 그 날 발주행 삭제 후 정산행 생성 |
| 출고재고현황 (재고 관리 밑) | 통합 SQL `selectStockOutByMonth` | ① 정산서 없는 날 = 발주행 ② 정산서 있는 날 = 정산수량을 같은 발주라인의 사업장에 비율 배분. 년월 칸에 「정산 n일 · 발주 m일」 셀 클릭 → 하단에 납기일자별 출고내역(`selectStockOutDetail`, 같은 규칙) + 입고내역(수불원장 I·R·A) |
| 납기현황표(대시보드) · 납기세부조회 | `selectShipoutMst` | 행마다 `settleYn`/`settleQty`. 정산서 있는 날은 화면 수량 = 정산수량(비율 배분). 배지에 「📄 정산서 반영 n건」 |
| 납기현황이력조회 · 택배납기관리 · 차수 매트릭스 | 발주현황표 그대로 | 업로드 차수·박스·라벨 같은 작업 화면이라 정산서로 바꾸지 않는다 |

## 원장 키 = 납기일자 (2026-09-03 전환)
- 종전엔 발주행 원장 `TRX_DT/REF_NO` 가 **출고일자(SHPOUT_DT)** 였고 정산행은 납기일자였다. 김해처럼 하루 먼저 나가는 곳(출고 D-1 · 납품 D)은
  정산서 D 가 와도 D-1 발주행이 안 걷혀 **두 번 빠졌다**(실측 42행). 이제 둘 다 납기일자라 갈아끼우기가 1:1 이다.
- 그래서 바뀐 것: `insertShipoutLedger`, `selectShipoutDates`, `selectShipoutDatesByProd`, 수불내역 사업장 조인(`selectStockLedgerList` 4곳),
  업로드 컨트롤러의 재동기화 날짜(발주행의 DLV_DT), 재집계 시작 때 `deleteShipoutLedgerAll`(옛 출고일자 키 잔재 제거, 마감 확정월 제외).
- ⚠ **배포 뒤 재고현황 [🔄 출고반영 재집계] 를 한 번 눌러야** 옛 키(출고일자) 행이 납기일자 키로 다시 만들어진다.

## 정산서 ↔ 사업장 (비율 배분)
- 정산서에는 사업장이 없다. 발주번호(ORD_NO)는 **물류센터 하루치 발주 하나**라 여러 사업장을 품는다.
- 같은 발주라인 = (납기일자, 발주번호, 품목 PROD_CD). 정산수량 × (그 사업장 발주수량 ÷ 라인 발주수량 합).
  평소엔 정산 = 발주라 그대로고, 반품·수량차만 비율로 흩어진다. 소수는 화면에서 반올림.
- 라인 키에 납기일자를 빼도 연결되는 라인은 똑같고(실측), 빼면 단일일자 조회가 0.2초→8초로 느려져 **납기일자를 키에 둔다**.
- **발주라인이 아예 없는 정산행**(발주번호가 발주현황표에 없음 — 호호솥밥 DC 대량분 등, 8월 26라인 952개)은 출고재고현황에 `(정산서·발주없음)` 사업장으로 나오고,
  대시보드에는 발주행이 없으니 안 보인다. 원장에는 들어간다.
- 발주번호가 빈 발주행(전체 1.7%)은 정산서가 있는 날이라도 라인을 못 찾아 대시보드는 발주수량 그대로, 출고재고현황·원장에서는 정산서만 센다.
