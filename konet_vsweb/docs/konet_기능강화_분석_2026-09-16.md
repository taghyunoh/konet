## ② 직송 오배송

### 지금 되는 것
- 직송 = 발주현황표 엑셀의 `존`·`배송구분` 두 칸 중 하나가 `'직송'`(`logi-oh.js:3451`). DB 는 `TBL_SHIPOUT_MST.ZONE`·`DLV_GB` 별도 칼럼(`User_SQL.xml:513`). 화면의 「평택물류센터1 직송」은 표시용 조립값(`logistics_demo1.jsp:2372-2373`).
- 집계 분리(배송/직송 합계) · 정렬(같은 입고장 바로 아래) · 빨간 글씨 · 택배 화면은 직송만(`selectParcelOutList` `User_SQL.xml:1701`).
- 택배 화면 방어 : 주소 빈 칸 빨간 테두리 · [주소없음 제외] · 엑셀 만들 때 확인창 · 마스터에 없는 사업장 `신규` 배지 · 「출력됨」 기록으로 중복 발송 방어(`parcelOut.jsp:237-276`).
- 업로드 행 검증(출고장·수량·품목코드·사업장명·납기일자 빈값) `logi-oh.js:1746-1790`.
- **변경 알림 바** = 날짜별→출고장별로 직전 배치와 현재 배치를 `사업장|품목` 키로 비교해 신규/증가/감소/삭제(`d2ChangeFromHist` `logistics_demo1.jsp:3456-3483`).

### 빠진 것
1. **「출고장이 바뀌었다」를 알려 주지 않는다.** 비교가 같은 zone 안에 갇혀(`:3460-3464`) 평택→김해 이동은 「평택 삭제 1 · 김해 신규 1」로 흩어진다. **배송→직송 전환도 같다**(zone 이름이 달라짐). 오배송의 가장 흔한 원인이 바로 이 자리.
2. 주소·거래처·출고장 정합성 검사가 **한 줄도 없다** — 「이 사업장은 늘 평택인데 이번만 김해」·「같은 주소 다른 사업장」·「사업장명과 주소 지역 불일치」 아무도 안 본다.
3. ⚠**결함 : 택배 [택배정보저장]이 수령자(`PARCEL_NM`)를 지운다** — 화면에 칸이 없는데(`parcelOut.jsp:410` 이 안 보냄) SQL 은 조건 없이 덮어쓴다(`updateBiziParcel` `User_SQL.xml:1670`). 거래처관리에서 넣은 수령자가 저장 한 번에 NULL.
4. `ZONE`/`DLV_GB` 불일치 가능성 — 대시보드는 OR, 택배 SQL 은 `ZONE` 만 → 대시보드엔 직송인데 택배 목록엔 없는 건이 생길 수 있다(실데이터 존재 여부는 추측).
5. 「출력됨」이 브라우저 한 대 localStorage — PC 바꾸면 중복 발송 방어가 사라진다(주석이 「필요해지면 서버로」 `parcelOut.jsp:245`).
6. 직송 낱알만 골라 삭제·정정하는 수단 없음(🗑 은 `DC_CD+INWH` 단위).

### 강화 제안
- ✅**P1-d 변경 알림에 「이동·전환」 유형 신설(완료 2026-09-16, 기본으로 늘 보임 — 사용자 확정)** — 비교 키를 zone 밖으로 꺼내 날짜별 `사업장|품목` 전체를 견주면, 삭제+신규 짝을 「평택1 → 김해3 이동」·「배송 → 직송 전환」으로 묶어 **빨간 경고**로 띄울 수 있다. **JSP 한 파일**(`d2ChangeFromHist`) 안에서 끝나고 DB 변경 없음. ②의 가장 값싼 큰 개선.
- ✅**P0-1 수령자 삭제 결함(완료)** — SQL 을 `PARCEL_NM = ISNULL(#{parcelNm}, PARCEL_NM)` 로(값이 안 오면 기존 값 유지). 택배 화면에 수령자 칸을 넣는 것은 별건.
- ✅**P0-3 택배 SQL 을 대시보드와 같은 OR 판정으로(완료)** — `selectParcelOutList` WHERE 를 `ZONE OR DLV_GB`.
- P2 「출력됨」 서버 저장(`TBL_SHIPOUT_MST` 에 출력 표식 또는 별도 표) · 통상 출고장 대비 이상 표시(사업장별 최근 N회 출고장 다수결과 다르면 배지).

- 원가 = 나간 수량 × 매입단가(`INPRICE_HST` 시점 최신 → `PROD_MST.IN_PRICE` → 0 '매입가없음') · 이중계상 방지 · 반품은 정산서(음수 행)·전표(부호 반전) 양쪽 상쇄 · 마감 스냅샷 `TBL_CLOSING_MST`.

### 빠진 것
1. **「순마진」이 매출총이익이다** — 택배비·운임·수수료·판관비를 담을 **테이블·컬럼이 없다**(`수수료|판관비|경비|물류비` 전 소스 0건). 운임 `PARCEL_FEE` 는 택배 출력용뿐.
2. 매입가 미등록 품목 = 원가 0 → 마진율 100%(7월 실측 306품목 미등록, 45개가 당월 판매). 배지만 있고 숫자는 부풀어 있다.
3. ⚠**판매전표 헤더 할인(`MST.DC_AMT`)이 마감·그래프에서 안 빠진다** — 채권·채무·일계장에서만 빠져 **같은 달 매출이 화면마다 다르다**(`User_SQL.xml:3762` vs `:2291-2336`).
4. 추정(②) 블록에 반품 개념 없음 → 정산서 도착 전 매출 과대.
5. 부가세 기준 혼재 — 전표는 `TOT_AMT`(세포함), 정산서 `SALE_AMT` 는 세액 분리 없음(정산서가 세포함인지는 **추측**).
6. 서비스(무상) 수량 원가 누락(`d.QTY` 만) — 재고원장 반영까지는 미확인.
7. 정산 그래프(demo2)는 시점 단가가 아니라 **최신 단가**(`logi-oh.js:6128-6160` 주석에 한계 명시). 대시보드 넓은표의 💰매출/🧾매입/📊마진 3행은 화면 메모리뿐(저장 안 됨, `logi-oh.js:430-446`).
