# 설계 — 적정재고 자동 산출 (2026-09-17)

[분석 문서](konet_기능강화_분석_2026-09-16.md) ① 「재고 파악이 안 돼 중복 발주」의 후속. 2026-09-16 에 만든 **적정재고 미달 강조 · 추천 발주**([설계](설계_적정재고미달_추천발주_2026-09-16.md))는 `TBL_PROD_MST.SAFE_STOCK` 이 들어 있는 품목만 지켜 준다. 그런데 운영 DB 실측 결과 적정재고가 들어 있는 품목은 **2,105 중 4** — 만든 기능이 놀고 있다. 이 문서는 「적정재고를 사람이 2,000개 넣는」 대신 **최근 출고로 자동 산출해 제안하고, 확인 후 일괄 적용**하는 설계다.

⛔**DDL 1개(칸 2개 추가)** · WAR 재빌드+재기동(자바·매퍼). 결정 ①~⑥ 은 사용자 확정 뒤 구현.

## 1. 산식 ← 결정 ①②③④

```
일평균 d  = 최근 W일 원장 출고량(IO_GB='O', REF_GB≠'MOVE') ÷ W          (W 기본 90)
적정 S    = ceil( d × (L + A) ÷ 입수 ) × 입수                                (L 리드타임일 · A 안전일수 — 기본 7 · 7)
대상      = 활성 · 거래중지 아님 · W일 안 출고 일수 ≥ N                         (N 기본 5)
상한      = W일 출고량 (L+A 가 W 를 넘는 설정은 막는다)
```

- **결정 ① 기간 W = 90일**. 180일도 고를 수 있게 하되 기본은 90 — 웰스토리 발주는 계절보다 월 단위로 움직인다(입고 간격 평균 30일).
- **결정 ② 리드타임 L + 안전일수 A = 7 + 7 = 14일**. 발주서→매입 연결이 없어 리드타임을 실측할 수 없으니 **회사 설정값**으로 둔다(회사 정보 수정 ▸ 기능 ▸ `SET_JSON.func.safeLeadDays / safeBufDays`, 택배 기본 운임 `parcelFeeDef` 와 같은 자리). 품목별 리드타임은 이번엔 안 한다 — 매입전환이 쌓이면 §6 에서 자동으로 잰다.
- **결정 ③ 간헐 품목(출고 일수 < 5)은 산출하지 않는다** — 168품목. 한 번 30개 나간 품목에 14일치를 잡으면 「적정 5」 같은 숫자가 생겨 미달만 늘어난다. 제안 표에는 「간헐」로 남겨 보이되 값은 비운다(수기로는 넣을 수 있다).
- **결정 ④ 음수 재고는 산출에 영향 없다**(산식이 재고를 안 본다). 단 **추천 발주의 부족 = 적정 − 가용** 에서 가용이 음수면 부족이 터진다(보냉팩은 −27,970 + 적정 4,352 = 32,322 추천). ⇒ `selectSafeStockShort` 의 가용 계산을 **음수 현재고는 0 으로** 바꾼다(음수 = 원장 오류이지 「그만큼 더 사야 한다」가 아니다). 이 한 줄은 기존 기능의 정정이라 결정 없이 같이 고친다. 음수 품목은 추천 표에 「⚠ 음수 재고 — 매입 등록 확인」 배지.

## 4. 규칙·엣지
- 원장 O 행은 **정산서 우선 규칙이 이미 반영된 값**이라(같은 날 정산서가 있으면 발주현황표 행이 없다) 이중 계산이 없다. DC 발주(PROD_KIND='DC')도 원장을 타므로 저절로 포함.
- 창고 이동(`REF_GB='MOVE'`)의 O 행은 출고가 아니다 — 제외.
- 서브코드로 나간 출고는 주코드 원장에 쌓이므로(월별 출고현황과 같은 규칙) 주코드에 산출된다. 서브코드 품목은 「간헐/없음」으로 남는 것이 정상.
- 입수 0/NULL 은 1 로 본다. 제안값이 현재 적정과 같으면 「바뀌는 것만」에서 빠진다.
- 상한 : 제안 S 가 W일 출고량을 넘으면 그 값으로 자른다(설정 실수 방지).
- 5,000줄 상한(기존 bulk 규칙) — 후보가 260 이라 여유.
- 막지 않는다 : 제안은 제안. 적용도 체크한 것만.

## 5. 검증
1. 적용 전 시뮬레이션 숫자(후보 260 · 적정 합 3,618 · 미달 119)와 모달 요약 줄이 같은지.
2. 상위 품목 손계산 : 9904013324 (160Ø PET 뚜껑) 90일 출고 1,835 → 일평균 20.39 → ×14 = 285.5 → 입수 300 이면 **300**. 9904013376 (샌드위치 펄프용기) 594 → 6.6 → 92.4 → 입수 500 이면 **500**(입수 배수 올림이 크게 잡는 예 — 표에서 눈에 띄게).
3. 수기 4건이 [덮어쓰기] 없이 그대로인지 · 상품관리에서 고치면 출처가 수기로 바뀌는지.
4. 적용 뒤 발주서 [⚠ 추천 발주] 배지 = 미달 수, 보냉팩 3종의 추천이 32,322 가 아니라 적정치인지(결정 ④).
5. `selectStockMstList` 속도 변화 없음(칸 하나), `selectSafeStockSuggest` 는 90일 원장 GROUP BY 한 번 — 실측 1초 안.
