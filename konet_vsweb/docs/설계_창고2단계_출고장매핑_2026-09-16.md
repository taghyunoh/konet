# 설계 — 창고 2단계 : 출고 자동연동을 창고별로 (2026-09-16)

[창고별 재고 1단계](설계_창고별재고_2026-09-16.md)의 남은 반. 1단계에서 매입·판매·조정·이동은 창고를 갖게 됐지만, **발주현황표·정산서로 자동 생기는 출고(O 행)는 전부 기본창고(WH1)에서 빠진다.**
다른 창고 물건이 센터로 나가면 제1창고 재고는 실제보다 적게, 그 창고는 많게 남는다 — 2단계는 이 출고에 창고를 붙이는 일.
✅**구현 완료(2026-09-16 같은 날, 사용자 「추천대로 진행해줘」)** — 결정 4 전부 추천안(출고장별 · 직송도 같이 · 소급 없음 · 마감 창고별 스냅샷 같이). 내역·검증 = **§5**. ⛔DDL [docs/sql/20260916_wh_stage2.sql](sql/20260916_wh_stage2.sql) 먼저.

## 0. 지금 (실측)

| 자리 | 상태 |
|---|---|
| `insertShipoutLedger`(발주현황표 → O) · `insertSalesLedger`(정산서 → O/R) | `WH_CD` = 기본창고 고정(서브쿼리). **품목 × 납기일자로 합산**(GROUP BY) — 출고장이 달라도 한 줄 |
| 발주현황표·정산서 행 | 출고장 코드/이름(`DC_CD`/`DC_NM`)이 있다. 직송 행도 센터(DC)가 있다(ZONE·DLV_GB='직송') |
| 출고장 표 `TBL_DC_MST` | 오늘 만든 단일 원천(코드·지역명·묶음·거래처·차례) — **창고 칸이 없다** |
| 재집계 `[출고반영 재집계]`(`rebuildShipoutLedgerAll`) | 전 기간 O 행을 지우고 다시 만든다 — 매핑을 넣으면 **과거까지 소급**되는 길 |
| 재고마감 `TBL_CLOSING_STOCK` | 품목 단위(창고 없음) |

## 1. 어느 창고에서 나가는가 — 매핑 축 ← 결정 ①

| 안 | 규칙 | 맞는 경우 |
|---|---|---|
| **A (추천)** | **출고장(센터)별** — `TBL_DC_MST.WH_CD` 한 칸 추가. 「용인·평택 → 제1창고, 오산센터 5곳 → 제2창고」처럼 센터가 어느 창고에서 실려 나가는지 | 창고가 **지역·동선**으로 나뉜 경우(대부분) |
| B | **품목별** — `TBL_PROD_MST.WH_CD`(그 품목의 보관 창고) | 창고가 **품목 성격**(냉장/상온·부피)으로 나뉜 경우 |
| C | 둘 다 — 품목 창고가 있으면 그것, 없으면 출고장 창고 | 섞여 있을 때. 규칙이 둘이라 「왜 이 창고에서 빠졌지」가 어려워진다 |

A 는 표 1칸 + 화면(창고 관리에 「출고장 → 창고」 줄)이면 끝. 매핑이 비면 **기본창고**(지금과 같음)라 안 채운 센터는 아무것도 안 바뀐다.

## 2. 직송 ← 결정 ②
직송 행도 센터 코드가 있으니 A 로 같이 간다(그 센터 담당 창고). 직송이 **창고를 안 거친다**(거래처→사업장 직배)면 창고 문제가 아니라 1단계 설계 §4 의 「재고를 안 타는 출고」 — 별건으로 답이 필요. 이번엔 **거친다**로 가정.

## 3. 만드는 것 (A 기준)

### ① 표
```sql
ALTER TABLE TBL_DC_MST ADD WH_CD VARCHAR(20) NULL;   -- 비면 기본창고
```
새 표 없음. `TBL_WH_ZONE_MAP`(1단계 설계에 적었던 것)은 `TBL_DC_MST` 가 생겼으니 필요 없다.

### ② 원장 SQL 2문 — 창고를 같이 묶는다
- `insertShipoutLedger` / `insertSalesLedger` : `WH_CD = ISNULL(dc.WH_CD, 기본창고)` (출고장 코드 = `dcKeyOf` 조각 → `TBL_DC_MST` 조인) · **GROUP BY 에 WH_CD 추가** → 같은 품목·같은 날이라도 창고가 다르면 O 행이 갈린다.
- `deleteShipoutLedger`·`deleteSalesLedger`(날짜 단위 삭제)는 그대로 — 창고 여러 줄도 함께 지워진다.
- 재고 계산은 이미 창고 필터가 있어 손댈 것 없음.

### ③ 화면
- **창고 관리**에 「출고장 → 창고」 표 한 장(출고장 7줄 × 창고 셀렉트, 비면 「기본창고」). 저장 = `TBL_DC_MST.WH_CD`.
- **창고별 재고현황**에 「출고장별 출고 창고」 안내 한 줄(어느 센터가 어느 창고에서 빠지는지).

### ④ 소급 ← 결정 ③
| | 뜻 |
|---|---|
| **이후 출고만(추천)** | 매핑 저장 뒤 업로드·재동기화되는 날짜부터 창고별. 과거 O 행은 기본창고 그대로 — 창고별 숫자가 맞으려면 **과거분을 창고 이동으로 한 번 맞춘다**(1단계 규칙) |
| 소급 | `[출고반영 재집계]`를 누르면 전 기간이 다시 만들어져 **과거까지 매핑대로 갈린다**. 이미 창고 이동으로 맞춰 둔 것과 겹치면 이중이 된다 — 재집계 버튼에 경고 한 줄 |
둘 다 코드는 같다(②가 재집계에도 그대로 쓰인다) — 「재집계를 누를 것인가」의 운용 결정.

### ⑤ 재고마감 창고별 ← 결정 ④
`TBL_CLOSING_STOCK` 에 `WH_CD` 를 더해 스냅샷·이월을 창고별로. 마감 확정 화면은 그대로(합계) 두고 스냅샷만 창고별로 쌓는다. 품 = DDL 1 + SQL 2(`selectStockClosing` GROUP BY 창고, `insertClosingStock`) + 자바 1줄. 지금 안 해도 1·2단계 동작엔 지장 없다(마감 합계는 창고와 무관).

## 4. 결정할 것 4
1. **매핑 축** — A 출고장별(추천) / B 품목별 / C 둘 다
2. **직송** — 센터 담당 창고에서 빠짐(추천, A 와 같이) / 창고를 안 거침(별건)
3. **소급** — 이후 출고만(추천) / 재집계로 과거까지
4. **재고마감 창고별 스냅샷** — 같이(작음) / 나중

품(A·이후만·마감 같이) = DDL 2칸 · SQL 4문 · 자바 2 · JSP 2 — 1단계의 1/4 정도. 검증 = 시뮬(매핑·기본창고 폴백·창고별 GROUP) + 가짜 날짜 왕복(발주현황표 업로드 → 두 창고로 갈린 O 행 → 창고별 재고현황).
