## 0. 먼저 바로잡을 것 — 「수기 이중장부」는 이미 메뉴에서 내려가 있다

분석 문서는 「수금/미수금 관리(`receiveMng`, `TBL_RECEIVE_MST`)가 매출과 단절된 수기 이중장부」라고 적었는데, 셸을 실측하니 **그 메뉴는 2026-07-25 에 이미 내려갔다**
(`logistics_demo2.jsp:3125` 주석 — 「'수금 등록'(건별 전표)이 같은 일을 하고 원장의 [월 계]로 월 합계까지 나온다. 두 군데 입력하면 잔고가 갈라져서 뺐다. **실사용 0건**」).
출금/미지급(`paymentMng`, `TBL_PAYMENT_MST`)도 같은 날 같은 이유로 내려갔다. 화면·컨트롤러·SQL·표는 **코드에 남아 있을 뿐**이다.

⇒ 지금 살아 있는 수금/미수 체계는 하나뿐이고, 이미 **자동**이다 :
- **수금 등록**(`rcvReg.jsp`) = 건별 수금 전표(`TBL_SETTLE_TRX`, `TRX_GB='RCV'`, 수금방법 `PAY_GB`·매출할인 `SALE_DC_AMT`)
- **거래처별 채권·채무**(`custBalance.jsp`, `selectCustBalance`) = 정산서 매출 + 판매전표 + 매입전표 + 수금/지급 전표를 **전 기간 누계**로 합쳐 거래처 × 월로 편다.
  받을금액 = (매출 − 매출할인) − 수금. 기초잔액 표 없이 **전표가 곧 원장**이라 어긋날 이중 소스가 없다.

그래서 이 과제는 「연동을 새로 만드는 일」이 아니라 **①죽은 수기 장부를 정리하고 ②살아 있는 자동 장부에 「미수 관리」로서 빠진 것을 채우는 일**이다.

## 1. 살아 있는 장부에 빠진 것 (코드 실측)

| 빠진 것 | 지금 | 근거 |
|---|---|---|
| **미수 연령** — 이 거래처의 받을 돈이 얼마나 오래됐나 | 「최근거래일」 한 칸뿐. 마지막 매출일·마지막 수금일이 따로 없고, 30일·60일 넘긴 미수를 가려낼 수 없다 | `custBalance.jsp:894-914` 열 = 거래처·구분·받을금액·지급할금액·순액·최근거래일·매출·수금·차액·매입·지급·차액 |
| **미수 있는 거래처만 보기 / 독촉 목록** | 필터 없음 — 425 거래처가 다 나오고 받을금액 0 이 대부분(매입처) | 같은 화면 |
| **월 마감 확정(굳히기)** | 잠금 표(`TBL_SETTLE_CLOSE_MST`, RCV/PAY × 월)와 확정/해제 엔드포인트(`receiveConfirm/Cancel/CloseStatus`)가 있으나 **수기 장부 화면만 썼다** — 수금 등록·채권·채무는 안 본다. 확정해도 전표는 그대로 고쳐진다 | `UserController.java:2864-2881`, `rcvReg.jsp`·`custBalance.jsp` 에 close 참조 0 |
| **확정 시점 숫자 보존** | 잔액이 늘 「지금 계산값」이라 전표를 소급 수정하면 지난달 잔액도 바뀐다 — 거래처에 보낸 미수 안내와 달라질 수 있다 | `selectCustBalance` 전 기간 누계 |

정산서 매출이 거래처에 붙는 길이 `DC_CD`(삼성웰스토리 7지점)뿐인 것은 **구조적 한계가 아니라 사실**이다 — 정산서를 주는 곳이 삼성 센터뿐이고, 나머지 매출은 판매전표에 `CUST_CD` 가 있다. 손댈 것 없음.

## 2. 설계

### ① 수기 장부 정리 (죽은 코드)
- 화면 `receiveMng.jsp`·`paymentMng.jsp`, 컨트롤러 `receive*.do`·`payment*.do`(목록·등록·수정·삭제·업로드·이월), 매퍼 `select/insert/update/delete/upsert/carryForwardReceive`(+Payment), DTO — **삭제**.
- 표 `TBL_RECEIVE_MST`·`TBL_PAYMENT_MST` 는 **남긴다**(실사용 0건이라 자료 걱정은 없으나, 표 삭제는 DDL 이라 사용자 몫).
- **월 마감(`TBL_SETTLE_CLOSE_MST`)과 확정/해제 엔드포인트는 살린다** — ③이 쓴다. 이름만 `settleClose*` 로.
← 결정 ①

### ② 채권·채무에 「미수 관리」 보강 (`custBalance.jsp` + `selectCustBalance`)
- SQL 에 거래처마다 **`lastSaleDt`(마지막 매출일) · `lastRcvDt`(마지막 수금일)** 추가(지금은 `lastDt` 하나).
- 잔액표에 **「미수 경과」** 칸 = 받을금액 > 0 이면 `마지막 수금일(없으면 마지막 매출일) 기준 경과일` → `정상(<30) · ⚠30일↑ · ⛔60일↑` 색 배지. 기준일수는 회사 설정(회사 정보 수정 「기능」)에 둔다 — 코드에 박지 않는다. ← 결정 ②
- 툴바에 **[미수 있는 거래처만]**(기본 켬 — 받을금액 > 0) · **[30일 넘긴 것만]** 체크. 425 줄에서 받을 돈 있는 열몇 줄만 남는다.
- 엑셀은 그대로(필터된 것만).
- ⚠**「특정일자와 잔액은 무관」(2026-07-27 사용자 확정)** 은 그대로 — 경과일은 누계 잔액 옆에 붙는 표시일 뿐 잔액 계산을 건드리지 않는다.

### ③ 월 마감 확정을 자동 장부에 연결
- 채권·채무 툴바에 **[🔒 이 달 마감 확정]**(기준월). 누르면 `TBL_SETTLE_CLOSE_MST('RCV', 기준월)` 확정 + 그 달의 거래처별 `매출·매출할인·수금·잔액` 을 **스냅샷**으로 저장.
  스냅샷 표는 새로 안 만든다 — **`TBL_RECEIVE_MST` 를 재활용**(칸이 그대로 맞는다 : `RCV_YM · BIZ_CD · PREV_AMT(이월) · SALES_AMT · COLLECT_AMT`). 수기 입력 대신 **자동 채움·읽기 전용**이 된다. 재고마감의 `TBL_CLOSING_STOCK` 과 같은 사고.
- 확정된 달은 **수금 등록·판매 등록에서 그 달 전표 저장·삭제 때 확인창**(막지 않는다 — 사용자 방침 「메시지 처리」) : 「2026-08 은 마감 확정된 달입니다. 그대로 저장하면 확정 당시 잔액과 달라집니다.」
- 채권·채무 월별 이력에 확정된 달은 🔒 + 「확정 잔액 vs 지금 잔액」이 다르면 빨간 차이 표시.
← 결정 ③ (회계 목적으로 굳힐 필요가 있는지 — 없으면 ③은 빼고 ①②만)
