## 0. 지금 코드에서 「창고」는 어디까지 있나 (실측)

| 자리 | 상태 |
|---|---|
| 재고 원장 `TBL_STOCK_LEDGER` | **창고 칸 없음**. 품목 × 일자 × 입출(I/O/R/A) 만. 현재고 = 전 원장 합(`selectStockQtyMap`) |
| 매입·판매 전표 헤더 `WH_CD/WH_NM` | 칸은 있으나 화면이 늘 `whCd:''`, `whNm:'물류창고'` 로 보낸다(`salesReg.jsp:1503`, `purchaseReg.jsp:1216`, 발주→매입 전환도 「물류창고」) — **글자 하나짜리 표시**, 재고와 무관 |
| 출고 자동연동 `insertShipoutLedger` | 발주현황표(정산서 우선) → 품목별 O 행. 어느 창고에서 나갔는지 **알 길이 없다**(발주현황표에 창고 없음 — ZONE·DC 는 «받는 쪽» 출고장) |
| 재고마감 `TBL_CLOSING_STOCK` | 품목 단위 기말 스냅샷. 창고 없음 |
| 창고 마스터 | 없음(`TBL_WH*` 0건). 셸의 「물품동선관리 ▸ 창고/로케이션 · 창고별 재고현황」은 **숫자를 박아 둔 데모 화면**(제1·2·3창고 샘플 품목 A·B·C) |

⇒ 프로그램 전체가 **창고 하나(물류창고)** 를 전제로 만들어져 있다. 「창고별」은 데모 메뉴의 이름뿐이다.

## 1. 먼저 정할 것 — 창고가 정말 둘 이상인가 ← 결정 ①

| 경우 | 뜻 | 권고 |
|---|---|---|
| **A. 하나다** — 물류창고 한 곳에서 다 나간다 | 창고별 재고는 «없는 문제». 지금 재고현황이 곧 창고 재고 | **P3 를 「안 함」으로 닫는다.** 데모 메뉴(창고/로케이션·창고별 재고현황·재고/위치 조회·출고지시)는 «예정·데모» 꼬리표를 달고 있으니 그대로 두거나 내린다 |
| **B. 둘 이상이다** — 예: 본창고 + 외부 보관(3PL) / 냉장·상온 / 지역 창고 | 「어느 창고에 몇 개」가 발주(①)에 실제로 영향 | 아래 §2 로 간다. **원장 구조 변경**이라 P1·P2 보다 큰 덩어리 |
| C. 창고는 하나인데 **직송분**이 창고를 안 거친다(거래처 → 사업장 직배) | 창고별이 아니라 **「재고를 안 타는 출고」** 문제 | 창고를 나누지 말고 직송 출고를 원장에서 빼는(또는 «통과» 표시) 별건 — §4 |

⚠지금 원장은 직송(ZONE/DLV_GB='직송')도 창고 출고(O)로 뺀다(`insertShipoutLedger` 에 직송 예외 없음). C 가 사실이면 재고가 실제보다 적게 보이고 있다 — 이건 창고 수와 무관하게 확인할 값어치가 있다.

## 2. 둘 이상일 때의 설계 (B)

### ① 표
```sql
TBL_WH_MST        ( COMP_CD, WH_CD PK, WH_NM, DEFAULT_YN, SORT_ORD, USE_YN, … )      -- 창고 마스터. 씨앗 = 'MAIN' 물류창고(DEFAULT_YN='Y')
TBL_STOCK_LEDGER  ADD WH_CD VARCHAR(20) NOT NULL DEFAULT 'MAIN'                      -- 기존 행 전부 MAIN 으로 이관(= 지금 재고 그대로)
TBL_CLOSING_STOCK ADD WH_CD (스냅샷도 창고별)
TBL_WH_ZONE_MAP   ( COMP_CD, ZONE(출고장·DC_CD), WH_CD )                                -- 출고장 → 어느 창고에서 나가나 (2단계)
```
매입·판매 전표 헤더의 `WH_CD` 는 그대로 쓰되 **실제 코드**를 넣는다(지금은 빈 값).

### ② 원장에 창고를 넣는 자리 — 5곳 (여기가 품의 대부분)
| 원천 | 지금 | 창고 |
|---|---|---|
| 매입등록 `PURCH` | 전표 헤더 창고 글자만 | 전표 창고 셀렉트(창고 마스터) → 원장 I 행 `WH_CD` |
| 판매등록 `SALE` | 〃 | 전표 창고 → O 행 (재고 부족 제한 `stockLimit` 도 **그 창고 재고**로) |
| 출고 자동연동 `SHIPOUT` · 정산서 `SALES` | 창고 모름 | **1단계 = 기본창고(MAIN)** · 2단계 = `TBL_WH_ZONE_MAP`(출고장 → 창고). 발주현황표에는 창고가 없으니 규칙으로만 정해진다 |
| 재고 일괄조정 `A` | 품목별 | 창고 셀렉트 |
| **창고 간 이동**(신설) | 없음 | 이동 전표 = 보내는 창고 O + 받는 창고 I 한 쌍(`IO_GB='T'` 또는 REF_GB='MOVE') — 없으면 재고를 옮길 길이 없다 |

### ③ 읽는 자리 — 전부 창고 축이 하나 더 생긴다
`selectStockQtyMap`(발주서 현재고·판매 재고제한) · `selectStockMstList`(품목별재고현황 — 창고 열 또는 창고 필터) · `selectStockClosing/InboundClosing`(재고마감) · 월별 출고현황 · 재고 일괄조정 · 대시보드 재고 카드.
★규칙 : **창고를 안 고르면 합계**(= 지금 숫자). 창고별 숫자는 «더 보는 것»이지 «대신 보는 것»이 아니어야 기존 화면이 안 흔들린다.

### ④ 화면
- 기준정보관리 ▸ **창고 관리**(마스터) · 매입/판매 전표의 창고 칸 → 셀렉트 · 재고현황·재고마감·일괄조정에 **창고 필터**(기본 «전체») · **창고 이동** 등록(작은 화면) · 2단계에 출고장→창고 매핑.
- 데모 메뉴 4개는 진짜 화면으로 갈아끼우거나 내린다(둘 다 두면 헷갈린다).

### ⑤ 단계
1. **1단계** = 표·이관(전부 MAIN) · 매입/판매/조정에 창고 · 창고 이동 · 읽는 자리 「창고 필터(기본 전체)」. 출고 자동연동은 MAIN 고정. ⇒ 이 단계까지가 «창고별 재고»의 8할.
2. **2단계** = 출고장→창고 매핑으로 자동연동 출고를 창고별로.
3. 재고마감 창고별 스냅샷·기말 이월.

품 = DDL 3 + 자바(원장 DTO·저장 5곳·이동 신설) + SQL ~15문 수정 + JSP 6~7 — **P1-b 보다 크다.** 원장 저장 5곳 중 하나라도 창고를 빠뜨리면 그 자리만 MAIN 으로 쌓여 창고별 숫자가 조용히 틀어진다(기본값이 있어 오류가 안 난다 — 그래서 위험).

## 3. 결정할 것 4
1. **창고가 둘 이상인가**(A/B/C) — **A 면 여기서 끝**(추천 : 사실을 확인하고, 하나면 P3 를 닫는다).
2. B 라면 **창고 목록과 기본창고**, 그리고 **출고 자동연동은 어느 창고에서 나가는가**(전부 기본창고 / 출고장별 매핑).
3. B 라면 **창고 간 이동 전표**를 만들 것인가(안 만들면 창고별 숫자를 맞출 길이 조정뿐).
4. C 라면 **직송 출고를 원장에서 뺄 것인가**(창고를 안 거치면 재고에서 빼면 안 된다) — 창고 수와 별개로 답이 필요.

## 4. 직송과 재고 (C 의 경우, 참고)
직송 = 거래처(매입처)에서 사업장으로 바로 가고 우리 창고를 안 거친다면, 지금은 (a) 매입등록으로 I 가 쌓이고 (b) 발주현황표로 O 가 빠져 **재고는 0 으로 맞지만 «창고에 있었던 적이 없는 물건»이 재고 이력에 섞인다.** 매입등록을 안 하면 재고가 음수로 간다.
답은 창고를 나누는 게 아니라 **직송 발주현황표 행에 «통과» 표시**(원장 O 를 안 만들거나 REF_GB='SHIPOUT_DIRECT' 로 재고 계산에서 제외) + 매입도 «직송 매입»으로 재고를 안 타게 하는 것 — 작은 수정(SQL 2~3곳 + 전표 거래구분 하나).
