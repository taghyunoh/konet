# 설계 — 적정재고 미달 강조 · 추천 발주 (2026-09-16)

[분석 문서](konet_기능강화_분석_2026-09-16.md) ① 「재고 파악이 안 돼 중복 발주」의 마지막 조각(P1-c 후반). 상품마스터의 **적정재고(`SAFE_STOCK`) 칸은 입력·저장·엑셀까지 되는데 아무도 읽지 않는다**(비교 코드 0건).
발주서에 현재고·적정·미입고 3칸(P1-a·b)이 생겨 「같은 것을 또 발주하는」 구멍은 막혔지만, 반대쪽 구멍 — **「떨어졌는데 발주를 안 하는」** — 은 아직 아무도 알려 주지 않는다. 이 설계는 그 반대쪽이다.
✅**구현 완료(2026-09-16 같은 날, 사용자 「추천대로 진행해줘」)** — 결정 6 전부 추천안. 내역·검증 = **§5**. ⛔DDL 없음 · **WAR 재빌드+재기동 필요**(자바·매퍼).

## 1. 「미달」의 뜻 ← 결정 ①

**가용 = 현재고 + 입고예정(미입고)**.
**미달 = 적정재고 > 0 이고 가용 < 적정재고**. 부족수량 = 적정재고 − 가용.

- 입고예정을 더하는 까닭 : 이미 발주한 물건이 오고 있는데 「미달」로 또 추천하면 그게 곧 중복 발주다(목적 ① 을 이 화면이 다시 어기게 된다). 발주서 「미입고」 칸과 같은 숫자(`selectPoRemainByProd`)를 쓴다.
- 적정재고 0(미설정) 품목은 **대상 밖** — 아무 표시 없음. 「적정재고를 넣은 품목만 지켜 준다」가 규칙. 적정을 안 넣은 품목이 몇 개인지는 재고현황 요약 줄에 「적정 미설정 N품목」으로 알려만 준다(결정 ②).
- 창고는 안 본다 — 적정재고가 품목 단위라 창고별 적정은 없다(창고별 재고현황에서도 **합계** 기준).
- 음수 재고는 이미 빨강(적정 여부와 무관, 종전 그대로).

## 2. 어디에 보이나

### 2-1. 품목별재고현황(①표) — 「적정」 열 + 미달 빨강 + [적정재고 미달만]
- `selectStockMstList` 에 `MAX(p.SAFE_STOCK) AS safeStock` 한 칸(이미 `TBL_PROD_MST p` 조인 있음).
- 열 : 현재고 · 입고예정 다음에 **적정**. 미달이면 현재고 칸 빨강 배경 + 툴팁 「적정 N · 가용 M(현재고+입고예정) · 부족 K」.
- 툴바 체크 **[적정재고 미달만]**([매칭코드 있는 것만] 옆, 같은 방식으로 `stkStatusRender` 필터). 요약 줄에 「⚠ 미달 **N**품목 · 적정 미설정 M품목」.
- ⚠원장에 기록 없는 미달 품목은 이 표엔 여전히 안 나온다 — 그건 2-3 추천 발주 목록이 맡는다(마스터 기준이라 빠지지 않음). 요약 줄에 「원장에 없는 미달 K품목은 발주서 ▸ 추천 발주에서」 한 줄.

### 2-2. 창고별 재고현황 — 합계 기준 미달 표시 (결정 ③)
- `selectStockByWh`(창고별 재고현황) 응답에 `safeStock` 한 칸(품목 단위). 합계 열 옆 **「적정」** 열, 합계+입고예정 < 적정이면 합계 칸 빨강. 체크 [미달만].
- 입고예정은 `selectPoRemainByProd` 를 화면이 한 번 더 부른다(발주서와 같은 길).

### 2-3. 발주서 — **[⚠ 추천 발주]** 단추 → 미달 품목 담기 (핵심)
- 단추 = 상단 단추 줄([＋ 새 발주서] 옆). 미달 품목 수를 배지로 「⚠ 추천 발주 **12**」(기준자료를 읽을 때 같이 센다). 0 이면 회색.
- 누르면 팝업(상품 선택 팝업과 같은 틀) : **체크 · 품목코드 · 품목명 · 규격 · 현재고 · 입고예정 · 적정 · 부족 · 추천 · 대표 매입처 · 최저 거래처 · 단가**.
  - **대표 매입처** = 그 품목을 가장 최근에 입고한 매입처(재고현황·재고마감과 같은 규칙) → 없으면 상품마스터 거래처.
  - **최저 거래처** = P2-b 와 같은 자료(`_vpc`). 대표 매입처보다 싸면 빨강.
  - **추천수량** = 부족을 **입수(`packQty`) 배수로 올림**(결정 ④). BOX 로 사는 물건을 낱개로 추천하면 어차피 고쳐야 한다. 입수 1 이면 부족 그대로.
- 목록 기준(결정 ⑤) : **발주서에 고른 거래처의 품목(대표 매입처 = 그 거래처) 먼저**, 팝업 안 토글 [전체 품목]. 거래처를 아직 안 골랐으면 전체. 발주서 한 장 = 거래처 한 곳이라, 전체를 보여 주면 「이건 다른 데서 사는 건데」가 섞인다.
- [선택한 N개 담기] → 기존 `prodAddSel` 과 같은 길(`prodFill`)로 줄을 만들고 **BOX/EA 칸에 추천수량**을 미리 넣는다(입수 배수면 BOX, 아니면 EA). 이미 담긴 품목은 팝업에서 「담김」 회색 + 체크 불가.
- ★**막지 않는다** — 추천은 제안. 수량은 언제든 고치고, 안 담아도 저장된다(사용자 원칙 「모두 강제는 아니죠 메시지 처리죠」).
- 새 SQL `selectSafeStockShort`(품목별 1줄, 마스터 기준) :
  `TBL_PROD_MST`(ACTION_YN='Y', SAFE_STOCK > 0) ⟕ 원장 합(현재고) ⟕ 발주 잔량(입고예정) ⟕ 최근 입고 매입처 → `WHERE SAFE_STOCK − (cur + remain) > 0`. 반환 = prodSeq·prodCd·prodNm·spec·packQty·inPrice·taxGb·safeStock·curQty·poRemainQty·shortQty·vendorCd·vendorNm. 엔드포인트 `/prod/safeStockShort.do`.
  ⚠원장 합은 `selectStockQtyMap` 과, 잔량은 `selectPoRemainByProd` 와 **같은 식**이어야 한다(세 화면 숫자가 같아야 믿는다) — 서브쿼리를 그대로 옮긴다.

### 2-4. 물류 관리 첫 화면(선택)
- 품목별재고현황 메뉴 글자 옆에 「⚠ N」 배지 정도. 이번엔 **안 한다** — 발주서·재고현황 두 곳이면 충분하고, 대시보드는 이미 배지가 많다. 필요해지면 `safeStockShort.do` 한 번 더 부르면 된다.

## 4. 결정할 것 5 (+⑥ 선택)

| # | 물음 | 추천 |
|---|---|---|
| ① | 미달 판정에 **입고예정을 더할까** | **더한다** — 안 더하면 발주해 둔 것을 또 추천(중복 발주) |
| ② | 적정재고 0(미설정) 품목 | **대상 밖**, 요약 줄에 개수만 |
| ③ | 창고별 재고현황에도 적정 열 | **넣는다**(합계 기준, 작다) |
| ④ | 추천수량 | **입수 배수로 올림**(BOX 칸에) — 부족 그대로는 툴팁에 |
| ⑤ | 추천 목록 범위 | **고른 거래처 품목 먼저 + [전체] 토글** |

⚠적정재고를 넣은 품목이 지금 몇 개인지는 DB 를 봐야 안다(`SELECT COUNT(*) FROM TBL_PROD_MST WHERE SAFE_STOCK > 0 AND ACTION_YN='Y'`). 0 에 가깝다면 이 기능은 **적정재고를 채우는 일**이 먼저다 — 상품마스터 엑셀 **내보내기**에는 적정재고 칸이 있지만 **일괄로 넣는 길은 없다**(품목 하나씩 폼). 품목이 많으면 「적정재고 일괄 입력」(엑셀 두 열 붙여넣기 : 품목코드·적정) 작은 화면을 이 일에 **같이 붙일지**가 결정 ⑥ — 추천은 「같이」(SQL 1 + JSP 1, 반나절 안).

★셈은 **세 화면이 같은 식** : 가용 = 현재고 + 입고예정, 미달 = 적정 > 0 이고 가용이 적정에 못 미침, 부족 = 적정 − 가용. 추천수량 = 부족을 입수 배수로 올림.
★적정재고를 안 넣은 품목은 **대상 밖**(요약 줄에 개수만). 거래중지 품목은 추천에서 뺀다.
★추천은 **제안일 뿐 막지 않는다** — 수량은 담은 뒤 고치고, 안 담아도 저장된다.

검증 = javac · 매퍼 XML 284문·id 중복 0 · **MyBatis 실제 파싱 bad 0** · 인라인 JS 4화면 0 오류 · 표 칸 수 대조(머리 11 = 총합계 11 = 품목 줄 11, 매칭코드 하위 줄 11) · node 시뮬 **26**(추천수량 7 · 미달 판정 6 · 붙여넣기 파싱 13).

⛔**눈 검증은 재빌드·재기동 뒤** : 상품코드관리 [📊 적정재고 일괄] 로 품목 두엇에 적정재고 넣기 → 품목별재고현황 「적정」 열·현재고 빨강·[적정재고 미달만] → 창고별 재고현황도 같은 품목이 빨강 → 발주서에 [⚠ 추천 발주 N] 배지 → 담으면 추천수량이 BOX/EA 에 → 저장하면 배지 수가 준다(입고예정이 늘어 미달이 풀린다).
