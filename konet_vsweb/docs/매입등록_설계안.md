# 매입등록 설계안 (wholedoc → konet_vsweb 이관)

> 목표 : 홀세일닥터(wholedoc.net) 매입등록을 konet_vsweb 으로 옮기되 **더 간단하고 편하게**
> 작성 : 2026-07-25 · 상태 : **설계안(미확정)** — DDL·화면 확정 후 착수

---

## 1. 옮겨올 기능 (원본 화면 기준)

| | 영역 | 원본 동작 |
|---|---|---|
| ① | 기간 매입 리스트 | 전표 목록 + 합계(매입·반품·매입계·지급계·할인계·미지급) |
| ② | 매입 명세 그리드 | 상품추가 → BOX/EA/합계수량 · 단가 · 금액 · DC · 공급가 · 부가세 · 매입금액 · 서비스 · 비고 · 행사 · 거래구분(매입/반품) |
| ③ | 거래처 분개장 | 일자별 매입·DC·지급·할인·잔고 + 월계 + 합계 |
| ④ | 복사저장 | 기존 전표를 다른 일자·다른 거래처로 복제 |
| ⑤ | 품목 매입단가 이력 | 거래처 × 상품 최근 3년 단가·수량·금액 |

## 2. 지금 konet_vsweb 상태

**있는 것**

| 자원 | 비고 |
|---|---|
| `TBL_VENDOR_MST` (36컬럼) | `ALIAS`·`CEO_NM`·`MGR_CD`/`MGR_NM` 보유 → ④ 거래처 검색 팝업 컬럼이 그대로 충족 |
| `TBL_STOCK_LEDGER` (22컬럼) | `VENDOR_CD/NM`, `UNIT_PRICE`, `AMT`, `IO_GB`, **`REF_GB`·`REF_NO`**, `REMARK` |
| `TBL_PROD_INPRICE_HST` | ⑤ 단가이력의 원천 |
| `TBL_PAYMENT_MST` | 출금/미지급 — **거래처 × 귀속월(`PAY_YM`) 단위** |
| `TBL_USER_MST` | 담당사원 |

**없는 것**

- **매입 전표라는 개념.** 지금은 상품(품목)관리 ▸ 재고 탭에서 품목을 **하나씩** 입고 등록한다.
  거래처를 고르고 여러 품목을 한 번에 넣는 화면이 없다.
- 전표 헤더 정보(전표번호·담당사원·창고·지급구분·지급액·할인액·메모)를 담을 곳.
- ③ 원장은 **일자별 잔고**가 필요한데 `TBL_PAYMENT_MST` 는 월 단위라 그대로는 못 만든다.

## 3. 설계 — 헤더 + 명세 2개, 재고원장은 **파생**

원본 화면 그대로 만든다(2026-07-25 확정 "이미지대로"). `BOX수량`·`EA수량`·`DC`·`서비스`·`행사` 를
모두 보관해야 하는데 `TBL_STOCK_LEDGER` 에는 그 칸이 없다 → **명세 테이블을 따로 둔다.**

```
매입 전표 1건
 ├ 헤더 : TBL_PURCHASE_MST     ← 신규
 ├ 명세 : TBL_PURCHASE_DTL     ← 신규 (BOX/EA/DC/서비스/행사/거래구분 보관)
 └ 재고 : TBL_STOCK_LEDGER     ← 전표 저장 시 자동 생성되는 **파생 기록**
            REF_GB = 'PURCH' · REF_NO = 전표번호 · IO_GB = 'I'(매입) / 'R'(반품)
```

**"이중 관리"가 되지 않게 하는 규칙 — 원본은 항상 전표다.**

- 재고원장 행은 **전표를 저장할 때만** 만들어진다. 사람이 직접 손대지 않는다.
- 전표를 수정/삭제하면 그 전표가 만든 원장 행도 **같이** 수정/삭제한다.
  역추적을 위해 명세에 `LEDGER_SEQ` 를 남긴다.
- 이렇게 하면 **재고현황·재고마감·매입마감이 지금 로직 그대로** 맞는다
  (매입마감 `selectInboundClosing` 은 `TBL_STOCK_LEDGER` 를 본다).
- 상품관리 ▸ 재고 탭의 기존 개별 입고와 한 원장에서 공존한다(`REF_GB` 로 구분).

### DDL (안)

```sql
CREATE TABLE TBL_PURCHASE_MST (
    PURCH_SEQ    int IDENTITY(1,1) NOT NULL PRIMARY KEY,
    PURCH_DT     varchar(8)    NOT NULL,   -- 매입일자 yyyymmdd
    PURCH_NO     varchar(4)    NOT NULL,   -- 그날의 순번 '0001'
    VENDOR_CD    varchar(20)   NULL,
    VENDOR_NM    nvarchar(100) NULL,
    MGR_CD       varchar(20)   NULL,       -- 담당사원 (TBL_USER_MST)
    MGR_NM       nvarchar(50)  NULL,
    WH_CD        varchar(20)   NULL,       -- 창고
    WH_NM        nvarchar(50)  NULL,
    TOT_BOX_QTY  decimal(19,2) NULL,
    TOT_EA_QTY   decimal(19,2) NULL,
    TOT_QTY      decimal(19,2) NULL,       -- 합계수량
    SUPPLY_AMT   decimal(19,2) NULL,       -- 공급가
    VAT_AMT      decimal(19,2) NULL,       -- 부가세
    TOT_AMT      decimal(19,2) NULL,       -- 매입금액
    DC_AMT       decimal(19,2) NULL,       -- 할인액(헤더)
    PAY_GB       varchar(20)   NULL,       -- 지급구분 현금/카드/외상
    PAY_AMT      decimal(19,2) NULL,       -- 지급액
    REMARK       nvarchar(500) NULL,       -- 매입메모
    ACTION_YN    char(1)       NOT NULL DEFAULT 'Y',
    REG_DTTM     varchar(19) NULL, REG_USER nvarchar(50) NULL, REG_IP varchar(45) NULL,
    UPD_DTTM     varchar(19) NULL, UPD_USER nvarchar(50) NULL, UPD_IP varchar(45) NULL
);
CREATE UNIQUE INDEX UX_PURCH_NO  ON TBL_PURCHASE_MST(PURCH_DT, PURCH_NO) WHERE ACTION_YN='Y';
CREATE INDEX        IX_PURCH_VEN ON TBL_PURCHASE_MST(VENDOR_CD, PURCH_DT);

CREATE TABLE TBL_PURCHASE_DTL (
    DTL_SEQ      int IDENTITY(1,1) NOT NULL PRIMARY KEY,
    PURCH_SEQ    int           NOT NULL,   -- → TBL_PURCHASE_MST
    ROW_NO       int           NOT NULL,   -- 화면 행번호
    PROD_SEQ     int           NULL,
    PROD_CD      varchar(20)   NULL,
    PROD_NM      nvarchar(200) NULL,
    SPEC         nvarchar(100) NULL,       -- [입수량]규격
    PACK_QTY     decimal(19,2) NULL,       -- 입수량 (BOX→수량 환산 근거)
    BOX_QTY      decimal(19,2) NULL,
    EA_QTY       decimal(19,2) NULL,
    QTY          decimal(19,2) NULL,       -- 합계수량 = BOX×입수 + EA
    UNIT_PRICE   decimal(19,2) NULL,       -- 단가
    AMT          decimal(19,2) NULL,       -- 금액
    DC_AMT       decimal(19,2) NULL,       -- 행 DC
    SUPPLY_AMT   decimal(19,2) NULL,
    VAT_AMT      decimal(19,2) NULL,
    TOT_AMT      decimal(19,2) NULL,       -- 매입금액
    SERVICE_QTY  decimal(19,2) NULL,       -- 서비스
    REMARK       nvarchar(200) NULL,       -- 비고
    EVENT_YN     char(1)       NULL,       -- 행사
    TRX_GB       varchar(10)   NULL,       -- 거래구분 '매입' / '반품'
    LEDGER_SEQ   int           NULL,       -- 이 행이 만든 TBL_STOCK_LEDGER 행 (역추적)
    ACTION_YN    char(1)       NOT NULL DEFAULT 'Y',
    REG_DTTM     varchar(19) NULL, REG_USER nvarchar(50) NULL, REG_IP varchar(45) NULL,
    UPD_DTTM     varchar(19) NULL, UPD_USER nvarchar(50) NULL, UPD_IP varchar(45) NULL
);
CREATE INDEX IX_PURCHDTL_MST  ON TBL_PURCHASE_DTL(PURCH_SEQ);
CREATE INDEX IX_PURCHDTL_PROD ON TBL_PURCHASE_DTL(PROD_CD, ACTION_YN);
```

`IX_PURCHDTL_PROD` 는 ⑤ 품목 매입단가 이력(거래처 × 상품)에 쓴다.

## 4. 방침 — 편의 기능은 다 가져오고, **입력 칸만** 줄인다

"간단하게"는 **손이 덜 가게** 한다는 뜻이지 기능을 빼는 게 아니다.
홀세일닥터에서 쓰기 편했던 것은 전부 옮긴다.

### 가져올 편의 기능

| 기능 | 무엇이 편한가 |
|---|---|
| **복사저장** | 같은 거래처에서 늘 비슷한 품목을 산다. 지난 전표를 일자·거래처만 바꿔 복제 |
| **품명 클릭 → 단가이력** | 그 거래처에서 이 상품을 얼마에 샀었는지 3년치를 그 자리에서 확인 |
| **최근 단가 자동 입력** | 품목을 고르면 그 거래처의 마지막 매입단가가 단가칸에 미리 채워짐 |
| **현잔고 / 거래후잔고** | 화면 상단에 미지급 잔고와 이 전표 반영 후 잔고를 같이 표시 |
| **[매입액] [전액] [털기]** | 지급액에 매입금액·전액을 한 번에 넣고, 잔돈은 할인으로 터는 버튼 |
| **BOX 입력 → 수량 자동환산** | 상품마스터 입수량으로 BOX×입수 = 합계수량 자동 계산 |
| **거래처 옆 원장 동시 표시** | 등록하면서 그 거래처 잔고·지급 이력을 바로 확인(3단계) |
| **거래명세서 인쇄** | 등록 즉시 출력 |

### 화면 칸은 원본 그대로 (2026-07-25 "이미지대로" 확정)

`상품추가 · 품명(단가이력조회) · [입수량]규격 · BOX수량 · EA수량 · 합계수량 · 단가 · 금액 · DC ·
공급가 · 부가세 · 매입금액 · 서비스 · 비고 · 행사 · 거래구분` — **전부 유지**한다.

"간단하게"는 **칸을 빼는 게 아니라 손이 덜 가게** 하는 것으로 푼다. 자동으로 채우는 것들:

| 칸 | 자동 |
|---|---|
| `[입수량]규격` | 품목 선택 시 상품마스터에서 |
| `합계수량` | `BOX × 입수 + EA` |
| `단가` | 그 거래처의 **최근 매입단가** (⑤ 이력의 최신값) |
| `금액` | `합계수량 × 단가 − DC` |
| `공급가` · `부가세` · `매입금액` | 상품마스터 `TAX_GB`(과세/면세)로 계산 |
| `거래구분` | 기본 '매입' |

결과적으로 사람이 치는 건 **품목 · BOX수량** 둘뿐이고, 나머지는 확인만 하면 된다.

## 4-2. 수금등록 · 지급등록 (2026-07-25 추가 요청)

매입등록과 같은 방식으로 **수금 등록**·**지급 등록**도 옮긴다. 두 화면은 구조가 사실상 같다.

| | 수금 등록 | 지급 등록 |
|---|---|---|
| 일자 | 수금일자 | 지급일자 |
| 구분 | 무통장입금 / 카드 | 무통장지급 / … |
| 계좌 | 우리은행 1005-201-931176 | 국민은행 699237-01-004560 |
| 거래처 | 매출처 + 담당자 | 매입처 + 담당자 |
| 잔고 | 현잔고 · **수금 후 잔고** | 현잔고 |
| 금액 | 수금액 · 할인액 · 합계금액 · **매출할인(DC)** | 지급액 · 할인액 · 합계금액 |
| 메모 | 있음 | 있음 |
| 하단 | 기간·구분·담당사원·거래처 검색 + 목록 + `수금계`/`할인계` | 동일 (`지급계`/`할인계`) |
| 우측 | 원장 (매출·DC·수금·할인·잔고) | 원장 (매출·DC·수금·**매입·지급**·할인·잔고) |

→ **테이블 1개로 둘 다 처리**한다. 기존 `TBL_SETTLE_CLOSE_MST` 가 `SETTLE_GB='RCV'/'PAY'` 로
수금·지급을 한 테이블에서 구분하는 것과 같은 방식이다.

```sql
CREATE TABLE TBL_SETTLE_TRX (
    TRX_SEQ      int IDENTITY(1,1) NOT NULL PRIMARY KEY,
    TRX_GB       varchar(3)    NOT NULL,   -- 'RCV'=수금 / 'PAY'=지급
    TRX_DT       varchar(8)    NOT NULL,   -- 수금일자 / 지급일자
    TRX_NO       varchar(4)    NOT NULL,   -- 그날의 순번 '0001'
    PAY_GB       varchar(20)   NULL,       -- 무통장입금 / 카드 / 현금
    ACCT_CD      varchar(20)   NULL,       -- 계좌
    ACCT_NM      nvarchar(100) NULL,       -- '우리은행 / 1005-201-931176 / (주)코네트'
    CUST_CD      varchar(20)   NULL,       -- 거래처 (수금=매출처, 지급=매입처)
    CUST_NM      nvarchar(100) NULL,
    MGR_CD       varchar(20)   NULL,
    MGR_NM       nvarchar(50)  NULL,
    AMT          decimal(19,2) NULL,       -- 수금액 / 지급액
    DC_AMT       decimal(19,2) NULL,       -- 할인액
    SALE_DC_AMT  decimal(19,2) NULL,       -- 매출할인(DC) — 수금 화면 전용
    TOT_AMT      decimal(19,2) NULL,       -- 합계금액
    REMARK       nvarchar(500) NULL,
    ACTION_YN    char(1)       NOT NULL DEFAULT 'Y',
    REG_DTTM     varchar(19) NULL, REG_USER nvarchar(50) NULL, REG_IP varchar(45) NULL,
    UPD_DTTM     varchar(19) NULL, UPD_USER nvarchar(50) NULL, UPD_IP varchar(45) NULL
);
CREATE UNIQUE INDEX UX_SETTLE_TRX_NO ON TBL_SETTLE_TRX(TRX_GB, TRX_DT, TRX_NO) WHERE ACTION_YN='Y';
CREATE INDEX IX_SETTLE_TRX_CUST ON TBL_SETTLE_TRX(CUST_CD, TRX_DT);
```

### 기존 월 단위 테이블과의 관계

`TBL_RECEIVE_MST`(수금·월) / `TBL_PAYMENT_MST`(지급·월) 는 **월 집계 화면용으로 그대로 둔다.**
건 단위 원천이 `TBL_SETTLE_TRX` 로 생기므로, 월 집계는 여기서 산출하거나 기존 화면을 유지한 채 공존시킨다.
(어느 쪽으로 갈지는 3단계에서 결정 — 지금 월 화면을 쓰고 계시면 건드리지 않는다)

### 원장(분개장) 구성

거래처 하나를 일자순으로 늘어놓고 누적 잔고를 낸다. 원천은 이미 다 있다.

| 열 | 원천 |
|---|---|
| 매출 | `TBL_SALES_MST` (정산서) |
| 매입 | `TBL_PURCHASE_MST` |
| 수금 · 지급 · 할인 | `TBL_SETTLE_TRX` |
| 잔고 | 누적 — 수금원장 `매출 − 수금 − 할인` / 지급원장 `매입 − 지급 − 할인` |

## 5. 단계

**1단계 — 매입 전표 등록 (①②)**
`TBL_PURCHASE_MST` 생성 → 등록/수정/삭제 → 저장 시 `TBL_STOCK_LEDGER` + `TBL_PROD_INPRICE_HST` 동시 반영.
화면 = 상단 입력 그리드 + 하단 전표 목록(기간·거래처 검색, 자동 스크롤 그리드).

**2단계 — 편의 기능 (④⑤)**
복사저장(목록 행 버튼 → 일자·거래처만 바꿔 복제), 품명 클릭 시 단가이력 팝업.

**3단계 — 거래처 원장 (③)**
일자별 매입·지급·잔고. **지급을 건 단위로 기록해야 한다** →
`TBL_PAYMENT_MST`(월 단위) 확장 또는 지급명세 테이블 신설이 필요. 1·2단계 뒤에 다시 설계.

## 6. 데이터 이관 — **엑셀 업로드**, 매핑표 불필요

**두 시스템이 이미 같은 코드를 쓴다.** 2026-07-25 실측으로 확인:

| 홀세일닥터 화면 | konet DB |
|---|---|
| 상품 `1010001004` | `1010001004` 98파이 PET 머그리드(Tall Lid),투명,1000EA/BOX · 매입가 18,700 |
| 상품 `1000762685` | `1000762685` 마시는리드,종이컵용,90파이12/16/20oz · 16,500 |
| 상품 `1010018004` | `1010018004` HOT스프용기뚜껑,350~474ML · 17,600 |
| URL `customerCode=0032` | 거래처 `0032` (주)에이에프프라텍 |
| 담당사원 김동근 | `MGR_NM` 김동근 |

거래처 **432건**, 상품 **1,940건**이 이미 적재돼 있고 화면에 보인 거래처 5곳이 코드까지 일치했다.
konet 마스터가 이미 홀세일닥터에서 넘어온 것으로 보인다.

→ **엑셀의 코드를 그대로 넣고, 마스터에 없는 코드만 골라 보고**하면 된다. 별도 매핑표를 만들 필요가 없다.
업로드 방식은 정산 엑셀·발주현황표와 동일한 검증된 패턴을 쓴다.

**주의** — 유사 상품이 중복 등록돼 있다. 코드로 넣으면 문제없지만 정리 대상이다.

```

```

## 7. 확정된 것 / 남은 것

**확정**

1. 이관 원본 = **엑셀 업로드**
2. 코드 매핑 = **불필요** (두 시스템 코드 동일 — §6)
3. 전표번호 = **일자별 `0001` 순번 유지** (원본과 동일)
