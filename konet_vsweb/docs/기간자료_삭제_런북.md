# 기간 지정 자료 삭제 런북

> 특정 기간(월/일자 구간)의 **거래 자료만** 골라 지우는 절차.
> 전체를 비우는 것은 [`sql/go_live_reset.sql`](../sql/go_live_reset.sql)(가동 전 초기화)을 쓴다.
>
> 최초 작성 2026-08-01 — 2026년 7월분 삭제를 실제로 수행하며 정리.

---

## 0. 먼저 알아둘 것

**되돌릴 수 없다.** 이 문서의 DELETE 는 트랜잭션으로 묶여 있지 않다.
백업을 받지 않고 실행했다가 잘못되면 복구 수단이 없다.

**기간 조건 컬럼이 표마다 다르다.** 아래 표를 보고 맞는 컬럼을 써야 한다.
일자는 전부 `yyyymmdd` 8자리 문자열이다(하이픈 없음 — 저장 시 `REPLACE(...,'-','')` 로 벗겨 넣는다).

| 자료 | 표 | 기간 컬럼 |
|---|---|---|
| 출고(발주현황표 업로드) | `TBL_SHIPOUT_MST` | `SHPOUT_DT` |
| 정산서(매출 엑셀 업로드) | `TBL_SALES_MST` | `DLV_DT` |
| 재고 수불원장 | `TBL_STOCK_LEDGER` | `TRX_DT` |
| 판매전표 | `TBL_SALES_TRX_MST` / `_DTL` | `SALE_DT` |
| 매입전표 | `TBL_PURCHASE_MST` / `_DTL` | `PURCH_DT` |
| 수금·지급 | `TBL_SETTLE_TRX` (`TRX_GB` = `'RCV'`/`'PAY'`) | `TRX_DT` |
| 매입단가 이력 | `TBL_PROD_INPRICE_HST` | `APPLY_DT` |
| 판매단가 이력 | `TBL_PROD_SALEPRICE_HST` | `APPLY_DT` |

**`ACTION_YN` 을 걸지 않는다.** 이 스크립트는 이력행(`ACTION_YN='N'`)까지 함께 지운다.
그래서 화면에서 보이는 건수보다 실제 삭제 건수가 훨씬 많다.
(2026-07 실측: 화면 기준 정산서 2,156건 → 실제 5,534행)

**수동 입출고 = `REF_GB` 가 빈 원장행.**
`TBL_STOCK_LEDGER` 는 원천이 두 가지다.

- `REF_GB` 가 있는 행(`SHIPOUT` / `PURCH` / `SALE`) = 전표·업로드가 만든 **파생**. 원본을 지우면 같이 지운다.
- `REF_GB` 가 비어 있는 행 = 사람이 손으로 넣은 **수동 입고·출고·조정**. 이것만 따로 지우려면 `ISNULL(REF_GB,'') = ''`.

코드에도 같은 구분이 있다 — `deleteStockLedger` 는 수기 조정 줄만 지우고 파생 줄은 건드리지 않는다.

## 1. 실행 전

### ① DB 백업 (필수)

```sql
BACKUP DATABASE KOLGSDB TO DISK='D:\backup\KOLGSDB_before_jul_del.bak' WITH INIT, COMPRESSION;
```

### ② 대상 건수 확인 (읽기만)

```sql
SELECT '출고(발주현황표)' 구분, COUNT(*) 건수 FROM TBL_SHIPOUT_MST  WHERE SHPOUT_DT BETWEEN '20260701' AND '20260731'
UNION ALL SELECT '수동 입출고·조정', COUNT(*) FROM TBL_STOCK_LEDGER WHERE ISNULL(REF_GB,'')='' AND TRX_DT BETWEEN '20260701' AND '20260731'
UNION ALL SELECT '수금(RCV)',       COUNT(*) FROM TBL_SETTLE_TRX   WHERE TRX_GB='RCV' AND TRX_DT BETWEEN '20260701' AND '20260731'
UNION ALL SELECT '지급(PAY)',       COUNT(*) FROM TBL_SETTLE_TRX   WHERE TRX_GB='PAY' AND TRX_DT BETWEEN '20260701' AND '20260731'
UNION ALL SELECT '판매전표',        COUNT(*) FROM TBL_SALES_TRX_MST WHERE SALE_DT  BETWEEN '20260701' AND '20260731'
UNION ALL SELECT '매입전표',        COUNT(*) FROM TBL_PURCHASE_MST  WHERE PURCH_DT BETWEEN '20260701' AND '20260731'
UNION ALL SELECT '정산서',          COUNT(*) FROM TBL_SALES_MST    WHERE DLV_DT   BETWEEN '20260701' AND '20260731';
```

0건인 구역은 실행할 필요가 없다.

### ③ `REF_NO` 형식 확인 (구역 D·E 를 쓸 때만)

전표 파생 원장은 `REF_NO` 로 원전표를 되짚어 지운다. 그 값이 실제로 전표 SEQ 인지 눈으로 본다.

```sql
SELECT DISTINCT REF_GB, REF_NO FROM TBL_STOCK_LEDGER WHERE REF_GB IN ('SALE','PURCH');
```

형식이 다르면(예: `yyyymmdd-0001` 같은 전표번호) 구역 D·E 의 서브쿼리를 그 형식에 맞게 고쳐야 한다.
안 고치면 전표는 지워지고 원장만 고아로 남는다.

## 2. 삭제

구역 간 의존 관계는 없다. 필요한 구역만 골라 실행하되, **`Z` 는 반드시 마지막**에 둔다.

```sql
/* ══ A) 출고(발주현황표) + 그 파생 원장 ═════════════════════════ */
DELETE FROM TBL_STOCK_LEDGER WHERE REF_GB='SHIPOUT' AND TRX_DT BETWEEN '20260701' AND '20260731';
DELETE FROM TBL_SHIPOUT_MST  WHERE SHPOUT_DT        BETWEEN '20260701' AND '20260731';

/* ══ B) 수동 입고·출고·조정 (전표 없이 손으로 넣은 수불) ═════════ */
DELETE FROM TBL_STOCK_LEDGER WHERE ISNULL(REF_GB,'')='' AND TRX_DT BETWEEN '20260701' AND '20260731';

/* ══ C) 수금 · 지급 ═════════════════════════════════════════════ */
DELETE FROM TBL_SETTLE_TRX WHERE TRX_GB IN ('RCV','PAY') AND TRX_DT BETWEEN '20260701' AND '20260731';

/* ══ D) 판매전표 (파생원장 → 명세 → 머리 순서) ═══════════════════ */
DELETE FROM TBL_STOCK_LEDGER WHERE REF_GB='SALE'
   AND REF_NO IN (SELECT CONVERT(NVARCHAR(20),SALE_SEQ) FROM TBL_SALES_TRX_MST
                   WHERE SALE_DT BETWEEN '20260701' AND '20260731');
DELETE FROM TBL_SALES_TRX_DTL WHERE SALE_SEQ IN (SELECT SALE_SEQ FROM TBL_SALES_TRX_MST
                   WHERE SALE_DT BETWEEN '20260701' AND '20260731');
DELETE FROM TBL_SALES_TRX_MST WHERE SALE_DT BETWEEN '20260701' AND '20260731';

/* ══ E) 매입전표 (파생원장·단가이력 포함) ════════════════════════ */
DELETE FROM TBL_STOCK_LEDGER WHERE REF_GB='PURCH'
   AND REF_NO IN (SELECT CONVERT(NVARCHAR(20),PURCH_SEQ) FROM TBL_PURCHASE_MST
                   WHERE PURCH_DT BETWEEN '20260701' AND '20260731');
DELETE FROM TBL_PURCHASE_DTL WHERE PURCH_SEQ IN (SELECT PURCH_SEQ FROM TBL_PURCHASE_MST
                   WHERE PURCH_DT BETWEEN '20260701' AND '20260731');
DELETE FROM TBL_PURCHASE_MST WHERE PURCH_DT BETWEEN '20260701' AND '20260731';
DELETE FROM TBL_PROD_INPRICE_HST WHERE APPLY_DT BETWEEN '20260701' AND '20260731';

/* ══ F) 정산서 (재고와 무관 — 매출·대사 자료) ═══════════════════ */
DELETE FROM TBL_SALES_MST WHERE DLV_DT BETWEEN '20260701' AND '20260731';
DELETE FROM TBL_PROD_SALEPRICE_HST WHERE APPLY_DT BETWEEN '20260701' AND '20260731';

/* ══ Z) 현재고 집계 비우기 — A·B·D·E 중 하나라도 했으면 필수 ════ */
DELETE FROM TBL_STOCK_MST;
```

### ★ `Z` 를 빠뜨리면 안 되는 이유

현재고(`TBL_STOCK_MST`)는 원장을 재집계해 만드는 파생표인데,
`recalcStockMstAll` 의 MERGE 에 **`WHEN NOT MATCHED BY SOURCE` 절이 없다.**

그래서 원장에서 어떤 품목의 행이 **전부** 사라지면, 그 품목은 MERGE 의 대상 자체가 되지 않아
`TBL_STOCK_MST` 에 **옛 수량이 그대로 남는다**(유령 재고).
재집계를 아무리 돌려도 안 없어진다. 통째로 비우고 다시 만들어야 한다.

## 3. 실행 후

### ① 남은 게 없는지

1. 위 **[1-②] 건수 확인 쿼리를 다시** 돌린다 → 실행한 구역은 전부 0.

2. 원장에 남은 원천 확인:
   ```sql
   SELECT REF_GB, COUNT(*) FROM TBL_STOCK_LEDGER GROUP BY REF_GB;
   ```
   지운 기간 밖의 행이 남는 것은 정상이다. 지운 구역의 `REF_GB` 가 남아 있으면
   [1-③]의 `REF_NO` 형식이 안 맞았다는 뜻이다.

### ② 마감이 떠 있는지

자료는 지웠는데 마감 기록만 남으면 "내용 없는 확정월"이 된다.

```sql
SELECT CLOSE_YM, STATUS FROM TBL_CLOSING_MST      WHERE CLOSE_YM = '202607';   -- 매출·매입 마감
SELECT CLOSE_YM        FROM TBL_CLOSING_STOCK     WHERE CLOSE_YM = '202607';   -- 재고 마감
SELECT CLOSE_YM        FROM TBL_SETTLE_CLOSE_MST  WHERE CLOSE_YM = '202607';   -- 정산(수금/지급) 마감
```

나오면 화면(**마감관리 ▸ 해당 마감**)에서 확정 해제하거나 그 행을 지운다.
확정월이 잠겨 있으면 이후 저장이 막힌다.

### ③ 재집계

**재고 관리 ▸ 재고현황 ▸ [🔄 출고반영 재집계]** 를 한 번 돌린다.
`Z` 로 비운 현재고가 남은 원장 기준으로 다시 만들어진다.

### ④ 눈으로 확인

- **재고현황** — 지운 기간의 출고가 빠져 수량이 늘었는지
- **매출내역 / 출고현황이력조회** — 해당 기간이 비었는지
- **원장관리 ▸ 거래처별 채권·채무** — 수금·지급을 지웠다면 잔고가 되돌아왔는지
