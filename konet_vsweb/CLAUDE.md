## ★[완료 2026-08-21] 단추 글자가 **두 줄로 접히는 현상** + 상단 [글자 축소·확대]

사용자 지적 — *「판매등록이나 수금등록에 버튼에 글자 (해상도) 커지면 두 줄로 생기는 현상 (전체적으로) 확인부탁,
그리고 공통적으로 자주쓰는메뉴 위치 우측에 글자 축소·확대 기능 구현」*

### ① 단추 글자 두 줄 — **모든 화면 공통 원인** (판매·수금만의 문제가 아니다)
- **증상** : 배율(Ctrl +)·해상도가 커지면 `＋ 신규등록` 같은 단추 글자가 두 줄이 되어
  높이 32~34px 짜리 단추 밖으로 삐져나온다.
- ★**원인** : 단추가 들어 있는 줄이 전부 `display:flex` 다. flex 칸은 자리가 모자라면
  **제 글자 폭보다 작게** 줄어들 수 있고(`min-width:auto` = min-content), 그 min-content 는
  ***띄어쓰기에서 끊은 가장 긴 낱말***이다 → 「＋」/「신규등록」 두 줄.
  높이는 px 로 박혀 있어 두 줄이 안 들어가 잘려 보인다.
  ⇒ ***조사 결과 이 프로젝트의 단추 규칙 중 `white-space` 를 가진 것은 하나도 없었다*** (전 화면 동일).
- **조치** : 새 공통 CSS **[css/winmc/konet-ui-fix.css](src/main/webapp/css/winmc/konet-ui-fix.css)** 한 장 —
  `button`·`.btn`·`.sa-btn`·`.pu-btn`·`.sv-btn`·`.cb-btn`·`.sd-btn`·`.sc-btn`·`.sh-btn`·`.db-btn`·탭에
  `white-space:nowrap` + `word-break:keep-all` + `flex-shrink:0`.
  nowrap 이면 min-content = 글자 전체 폭이라 **flex 가 그 아래로 줄일 수 없다** → 두 줄이 될 수 없다.
- ⚠**konet-notebook.css 에 넣으면 안 된다** — 그 파일은 노트북 전용 `@media` 라
  ***정작 큰 화면(=증상이 나는 곳)에서 한 줄도 안 걸린다.*** 그래서 **늘 적용되는 파일을 따로** 만들었다.
- **거는 자리** : 각 화면의 `konet-notebook.css` `<link>` **바로 아래**(그 화면 `<style>` 뒤).
  **전 화면 적용 완료(23개 JSP)** — konet-notebook 을 안 쓰는 `stockAdj`·`logistics` 는 `ui-concept.css` 아래에 걸었다.
  ⚠***새 화면을 만들면 이 한 줄도 함께 걸 것.***
- 수금·지급 작업줄(`<div style="display:flex; gap:6px; margin-top:10px">`)만 `flex-wrap:wrap` 을 더했다 —
  판매·매입의 `.sa-row`/`.pu-row` 는 이미 `overflow-x:auto` 라 넘치면 그 줄만 가로로 밀린다.

  첫 진입(100%) = 원래 크기보다 4% 작게. *아래 1.2 이력은 그 전 단계다* :
  *[이력]* 2026-08-21 하루에 네 번 옮겼고, ***그 과정이 곧 근거다*** :

- ★**왜 font-size 가 아니라 `zoom` 인가** : 이 앱 CSS 는 글자·칸 높이·표 폭이 **전부 px**다.

### ③ 밀도 — **여백·표 줄높이를 줄여 한 화면에 더 담는다** (konet-ui-fix.css §3)
사용자 요청 *「여백이랑 표 줄높이 줄여서 한 화면에 더 들어오게」* — ②의 배율 실랑이 끝에 나온 **진짜 해법**이다.
배율은 글자와 여백을 **같이** 키우고 줄여 아무것도 못 얻는다. **글자는 그대로 두고 빈 자리만 걷어내면** 둘 다 얻는다.
- **줄인 것** : 화면 바깥 위·아래 여백(14~16 → 8) · 제목 `h2` 20 → 17 · 소제목 아래 여백 12 → 5 ·
  카드 안쪽 여백·사이 간격 10~12 → 8 · 조작줄/탭 아래 여백 → 6 · **표 칸 세로 여백**(머리글 → 4, 값 → 3, `line-height:1.25`) ·
  셸 패널 `.logi-wrap .card` 18/20 → 12/14 · `#favBar` 위아래 8 → 5.
- **안 건드린 것** : **표 글자 크기** · **좌우 여백**(줄이면 글자가 세로 구분선에 붙는다) ·
  **입력칸·단추 높이**(화면 규칙 4 의 38/34/29 는 사용자 확정값).
- ⚠★**특이성 함정 — 여기서 한 번 헛짚었다.** `table td` 는 (요소 2개)뿐이라
  화면 CSS 의 `.sv-list td`(클래스1+요소1)에게 **진다.** 이 앱의 표는 거의 다 이름을 달고 있어
  ***`table td` 만 써 두면 대부분의 화면에서 한 줄도 안 줄어든다.***
  ⇒ `[class*="list"] td` 처럼 **이름 조각**으로 잡아 특이성을 같게 맞추고, **뒤에 실려서** 이긴다.
  ⇒ `ui-concept.css` 의 `.card thead th` 는 이 파일보다 **뒤에** 실리는 화면이 있어 이름 조각으로도 못 이긴다
    → 그것만 `.card table thead th`(요소를 하나 더)로 넘어선다.

IDENTITY(…_SEQ) PK와 `TBL_CODE_MST/DTL`(회사 공유 공통코드)은 제외.

## ★거래처별 품목 표기(교차참조) — TBL_PROD_XREF (2026-08-01 신설)
**코네트 품목은 하나. 거래처가 요청하는 코드·품명은 이 표에 N건. 가상코드는 만들지 않는다.**
- **왜**: 거래처(출고장)가 같은 물건을 자기 코드·자기 품명으로 요청한다. 종전에는 표기마다 `TBL_PROD_MST` 에 '가상코드'를 등록해 맞췄고 → **재고가 원코드/가상코드로 갈라졌다.** 근본 원인은 SQL 이 `pm.PROD_CD = t.ITEM_CD` 로 **거래처 코드=우리 코드를 전제**한 것(User_SQL.xml **17군데/6구문**: selectClosing·selectSalesChart·selectSalesChartDaily·selectShipoutMst·selectStockLedgerList·insertShipoutLedger). 표기를 담을 자리가 없었다.
- **DDL** [sql/prod_xref_ddl.sql](sql/prod_xref_ddl.sql) — `TBL_PROD_XREF` + `TBL_SHIPOUT_MST`/`TBL_SALES_MST` 에 `PROD_SEQ·PROD_CD` 추가(재실행 안전). **운영 DB 1회 실행 필요.**
- **★역방향 유일성**: `(COMP_CD, VENDOR_CD, DC_CD, EXT_ITEM_CD)` UNIQUE(`ACTION_YN='Y'` 필터) — (거래처+그쪽 코드)→우리 품목은 **1개**여야 업로드 행이 어디로 갈지 정해진다. 반대(우리 품목→거래처 코드 N개)는 정상. 위반 시 컨트롤러가 409 로 안내.
- **★원본 보존**: 업로드 `ITEM_CD/ITEM_NM` 은 거래처가 준 값 그대로 둔다. `PROD_SEQ` 칸만 덧붙인다. 출고서 품명 = `ISNULL(XREF.EXT_ITEM_NM, PROD_MST.PROD_NM)` → **요청한 이름으로 나간다.**
- **해석은 배치 단위 UPDATE 한 문장**(`resolveShipoutProd`/`resolveSalesProd`) — 행마다 조회하지 않는다. 컨트롤러 삽입 위치 = **INSERT 루프 직후·재고연동(A) 직전**. `PROD_SEQ` NULL = 미매핑 → 재고연동에서 자연히 빠짐(별도 조건 불필요).
- **★소급 반영**: `saveXref` 가 저장 후 같은 문장을 품목 기준으로 다시 돌려 **과거 업로드분을 채우고**, `selectShipoutDatesByProd` 로 그 품목 출고일자만 골라 원장 재생성. 이 한 걸음이 빠지면 "연결했는데 재고가 그대로"가 된다.
- **★추천 근거를 서버가 스스로 확보한다 (2026-08-01)** — 발주현황표에는 **규격도 단가도 없어서** 화면이 품명밖에 못 보내고, 그러면 정작 못 믿는 품명으로만 추천하게 된다(실제로 "추천 후보 없음"이 떴다). 그래서 `selectXrefCandidates` 가 `;WITH pv` 로 **같은 `ITEM_CD` 의 최근 정산서(TBL_SALES_MST)에서 `SALE_PRICE`·`SPEC` 을 끌어와** 단가·규격 대조에 쓴다(화면이 `extPrice`/`extSpec` 를 직접 주면 그쪽 우선). 화면은 `extItemCd` 를 반드시 함께 보낼 것.
- **★품명 비교는 '통째 포함' 이 아니라 '조각'** (2026-08-01) — 거래처 품명과 우리 품명은 **가운데·끝이 자주 다르다**(`(뜨돈)소스용기,95파이*H47MM,200ML,…` vs `(뜨돈)소스용기,95파이*H47MM(소,200ML,…`). 서로를 포함하지 않아 통째 비교로는 **후보 0건**이 나왔다(사용자가 직접 찾기로 `소스용기,95파이` 를 치면 바로 나오는데 추천만 못 잡았다). → CTE `nk` 가 공백 뗀 **앞 10자(pre10)** 와 **맨 앞 괄호묶음을 뗀 8자(core8)** 를 만들어 LIKE 비교(앞이 같으면 45, 조각만 같으면 35).
- **★품명은 못 믿는다(사용자 지적)**: 거래처는 코드뿐 아니라 **품명도 자기 식으로** 보낸다. 그래서 `selectXrefCandidates` 후보 점수는 **단가 95 > 규격 80 > 이전 표기 85/55 > 그 거래처 취급품목 30 > 품명 유사 25**. 단가가 1순위인 근거 = 정산 엑셀 단가는 우리 **출고단가**와 일치(평택 6건 중 5건, 매입단가 일치 0건). 발주현황표에는 규격·단가가 **아예 없어** 품명뿐이다.
- **확인(대사) 시점 = 2단계**: ①발주현황표 업로드 → 잠정 연결(`CONFIRM_YN='N'`, 재고는 바로 반영 — 출고는 이미 나간 사실) ②정산서 업로드 → 단가·규격 대조 후 [확인]으로 확정. **자동 확정 경로는 두지 않는다.**
- **미매핑 vs 미확인은 다르다**: 미매핑=어느 품목인지 모름 → 재고 반영 **불가**(보류) / 미확인=품목은 알고 도장만 안 찍힘 → 재고 반영 **가능**.

## ★새 상품코드는 「9」로 시작 (2026-08-12 확정)

- **창을 열면 그 코드가 이미 코드 칸에 들어가 있다**(칸이 select 되어 있어 그냥 쳐서 바꾸면 된다). **9가 아닌 코드도 막지 않는다** — 원천 코드를 손으로 넣어야 할 때가 있어 안내만 한다.

- **왜 대체를 없앴나**: 종전엔 가장 적게 쓴 자리를 자동으로 갈아치웠다 → 다른 화면을 몇 번 들락거린 것만으로 늘 쓰던 메뉴가 소리 없이 사라지고, **있던 자리에 손이 갔다가 엉뚱한 화면**이 열린다. `FAV_USE`(사용 횟수)는 이제 **칩 툴팁 표시용일 뿐** 배치를 정하지 않는다.
- **내리는 길은 칩의 ✕(`favDrop`) 하나뿐.** 비운 칸은 *다음에 여는 메뉴*가 채운다(내리자마자 저절로 들어오지 않는다).
- **☆(사이드바)도 같은 규칙** — `favToggle` 이 가득 차 있으면 **넣지 않고 알린다**(여기서만 대체하면 규칙이 두 벌이 된다). ☆ 는 이제 '📌 표시 + 담는 통로' 구실.
- **`FAV_DEFAULT=[]`** — 첫 진입은 **빈 줄**. 기본값을 미리 넣으면 자리가 처음부터 다 차 있어(대체가 없으므로) **내 메뉴가 영영 못 들어온다**. 빈 줄의 뜻은 `#favHint` 가 알린다.
- **★보관 키 판을 올렸다**: `konetLogiFav3` / `konetLogiFav3Set` / **`konetLogiFavOrder2`**. 쓰던 브라우저에 **옛 기본 7개**(매출내역·판매 등록…)가 남아 있으면 새 규칙에서 영영 안 빠지기 때문. **규칙을 또 바꿔 옛 저장값이 걸림돌이 되면 같은 수를 쓸 것**(v2 때도 같은 이유로 올렸다 — 아이콘 섞인 이름).
- 식별은 `data-key` 가 아니라 **메뉴 이름**(`favLabel` = 글자 노드만 — 아이콘·☆ 제외). 실행은 원래 메뉴의 `a.click()` 을 그대로 부른다(화면 여는 방법을 두 벌로 만들지 않는다).
- 설명서 `panel-guide` **`0-1. 화면 맨 위 공통 줄`** 에 같은 내용이 있다 — **규칙을 고치면 거기도 같이.**
