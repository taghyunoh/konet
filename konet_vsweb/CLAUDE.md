# konet_web 프로젝트 메모

## 스택/구조
- **MSSQL** + egovframework + MyBatis, 패키지 `egovframework.sejong`
- 뷰: Apache Tiles. `.raw/*` = tiles 래핑 없는 단독 페이지, `.main/*` = 표준 레이아웃(main.jsp+top.jsp, top.jsp는 사실상 비어있음 — 실제 네비 없음)
- **물류관리 화면은 `.raw/main/admin/logistics_demo2.jsp`(약 3000줄) 단독 셸** — 좌측 사이드바 + 모든 패널 + JS를 한 파일에 내장. 대시보드1(출고현황표)=`logistics_demo1.jsp`(iframe 로드). 사이드바 메뉴 onclick이 demo2 내부 함수/패널에 강결합 → 리팩터링 시 주의.
- 컨벤션: PK `XXX_SEQ IDENTITY`, 품목연결 `PROD_SEQ`+`PROD_CD`, 금액 `DECIMAL(18,2)`, 일자 `NVARCHAR(8)'YYYYMMDD'`·일시 `NVARCHAR(19)`, 소프트삭제 `ACTION_YN`, 감사컬럼 `REG_/UPD_`. 날짜 저장 시 `REPLACE(...,'-','')`. XML `<=`/`<` 는 CDATA 필수.

- 적용일/거래일 기본값 = 오늘(진입 시 + 품목 클릭 시).
- **테이블 4개**(DDL: `sql/logistics_price_stock_ddl.sql` 1~4): `TBL_PROD_INPRICE_HST`(매입가이력), `TBL_PROD_SALEPRICE_HST`(판매가이력), `TBL_STOCK_LEDGER`(수불원장), `TBL_STOCK_MST`(현재고집계)
- 매입가/판매가 등록 → `TBL_PROD_MST.IN_PRICE/SALE_PRICE` 동기화. 재고 수불 입출고 → `recalcStockMst`(MERGE)로 현재고·이동평균 재집계.

- 상품 삭제 가드: 연관(이력/재고) 있으면 삭제 차단(`countProdRelated`).
- DTO: ProdInpriceDTO/ProdSalepriceDTO/StockLedgerDTO/StockMstDTO. 엔드포인트 `/prod/inprice*·saleprice*·stock*`.
- **매출단가(조회) 탭 신설(2026-07-18)**: `TBL_SALES_MST` 조회 전용(납품일자·출고장·발주번호·판매단가·출고량·매출액·원본파일 + 상단 요약). 기존 `/sales/selectSalesMst.do`를 `itemCd`로 호출 — 서버코드 무변경, 화면에서 품목 필터 이중 적용(재시작 전 대비). **판매가 탭은 자체 입력 이력 전용 유지가 사용자 확정 방침** — TBL_SALES_MST를 판매가 이력 조회에 UNION 연계했다가 같은 날 원복함(다시 섞지 말 것).
- **수불 내역 사업장 표시(2026-07-18)**: `selectStockLedgerList` — SHIPOUT 자동연동 행은 BIZ_CD가 NULL(품목·일자 합산이라)이므로 `TBL_SHIPOUT_MST`에서 같은 품목+출고일자(REF_NO)의 BIZ_NM을 STUFF/FOR XML로 콤마 연결해 표시(CUR_QTY>0 활성분). 화면(재고현황 `stkLedgerDetail`)은 여러 곳이면 첫 곳+`＋N` 클릭 펼침(`_bizCell`/`_bizToggle`, logistics_demo2.jsp).

## 매출내역 = 정산서 업로드 + 출고 대사 (매입·재고관리 ▸ 매출내역) — TBL_SALES_MST × TBL_SHIPOUT_MST
**★성격 정정(2026-07-22, 사용자)**: 이 엑셀은 견적이 아니라 **정산서**다 — 출고장에 들어간 물품에 대해 **얼마를 받을지** 확정한 문서. 그래서 화면을 **견적서관리 ▸ 매출 엑셀 업로드 → 매입·재고관리 ▸ 매출내역**(입고내역 바로 밑)으로 옮겼다. 견적서관리 서브메뉴에서 '매출 엑셀 업로드'는 삭제.
- 메뉴명은 같은 날 **출고내역 → 매출내역**으로 한 번 더 바뀜(사용자). 화면 성격이 '출고 목록'이 아니라 '받을 금액'이라서.
- **내부 식별자는 `outHist` 그대로**(패널 `panel-outHist`, 함수 `oh*`) — 라벨만 바뀐 것이니 코드에서 `outHist`를 찾으면 이 화면이다. 사이드바에 남아있는 데모 패널 `panel-outboundList`('출고내역 / 거래명세서')와 혼동 금지(도달 불가·무관).
- **화면 4탭**(모두 JSP 내장 JS. 서버 무변경 — 기존 조회 API 2개를 합칠 뿐). **집계 2 × 원본 2 가 아니라 축 3 + 원본 1** 로 정리됨(2026-07-22, ②와 ④가 겹쳐 보인다는 사용자 지적 → ④를 사업장축으로 전환):
  ① **출고장별 합계** = 출고건수·출고수량(SHIPOUT) ↔ 정산행수·정산수량·평균단가·**정산금액(받을 금액)** + 수량차이·상태뱃지
    - **★상태는 수량차이만으로 판정하지 않는다(2026-07-22 보완)**: `정산에만 5개 + 출고에만 5개` 면 수량합 차이가 0이라 종전 로직이 **'일치'로 오진**했다. `_ohRoll`이 출고장별 대사키 집합(`sKeys`/`oKeys`)을 들고 **짝 없는 키 수**(`oOnly`=미정산 / `sOnly`=출고미상)를 세어, 하나라도 있으면 '일치'로 부르지 않고 뱃지 옆에 건수를 띄운다. 요약줄에도 총건수 표기. (합성 케이스로 오진→감지 확인)
  ② **출고장 ▸ 품목** = 품목축. 어느 품목이 어긋났나. 그룹 접기/펼치기 + 소계
  ③ **출고장 ▸ 사업장** = 사업장축, **출고수량 전용(금액 없음)**. 사업장 줄을 펼치면 출고 원본행. 하위는 기본 접힘(`_ohIsCol2(k,true)`), 접기키 접두사 `s:`/`b:` 로 ②(`i:`)와 분리. 맨 오른쪽 「정산 대사」는 **대사됨/미정산/대사불가** 상태만(배분 아님·사실)
  ④ **정산서 원본(엑셀)** = 정산서 행 그대로 + 출고수량 열. **출고장별 묶음 + 접기/펼치기 + 소계**(2026-07-22, 접기키 `t:`). ★소계의 출고수량은 **대사키 distinct 합** — 같은 (발주일자·출고장·품목) 정산행이 2개면 두 행 모두 같은 출고합계를 표시하므로 그냥 더하면 이중계상된다(`used` 가드)
- **출고장 코드↔이름 매핑은 `KONET_DC` 한 곳**(2026-07-22 통합). 종전에는 `SLS_DCCD`(이름→코드)·`_OH_CDNM`(코드→이름)·정규화 로직이 **따로 3벌**이라 한쪽만 고치면 조용히 어긋났다. 이제 `KONET_DC`(코드→이름) 하나만 고치면 역맵(`KONET_DC_R`)은 자동 생성. 공개 함수 = `konetDcShort`(표기 통일) / `konetDcCd`(이름→코드) / `konetDcNmOf`(행→지역명, DC_CD 우선). `slsDcCd`·`_ohDc`·`_ohDcOf` 는 호출부 유지용 얇은 별칭. **대시보드·매출마감의 오산센터 묶음(`CLOSE_DCGROUP`/`SS_DCGROUP`)은 성격이 다른 표라 합치지 않음**(그 둘끼리는 여전히 중복 — 별건)
  - 한쪽 원천이 통째로 없으면 빈 표 대신 **왜 비었는지 안내**(`_ohEmptyRow`) — 정산서만 없는 날/발주현황표만 없는 날을 구분해 문구가 달라진다.
  - **★출고장 묶음 = 4탭 공통 2단 트리**(2026-07-22 — 처음 '개별만' → "묶고 한 단계 더" → "매출내역 전체 공통"). 1단 = 대시보드 묶음(`CLOSE_DCGROUP` 오산센터 = 왜관·김해·광주·제주·오산, 매출마감과 동일 규칙) / 2단 = 개별 출고장(**돈의 기준** — 정산서·거래처가 출고장별이므로 여기 금액이 정산 대조 단위).
    - 공용 함수 `_ohDcGrp(지역명)` = `CLOSE_DCGROUP[KONET_DC_R[지역명]]` — 기존 매핑 재사용, 새 표 안 만듦.
    - **묶음이 2곳 이상일 때만 머리행**을 만든다(용인·평택은 혼자라 그냥 한 줄). 접기키 `d:`①/`d2:`②/`d3:`③/`d4:`④ — 탭마다 독립, **기본 펼침**(`ohGrp` 의 `/^d\d*:/` 분기가 `_ohAllCol` 을 타지 않게 막는다).
    - 탭별 단수: ①=묶음→출고장 / ②=묶음→출고장→품목 / ③=묶음→출고장→사업장→원본행 / ④=묶음→출고장→정산행. 페이지가 중간에서 시작하면 **상위 헤더를 순서대로 문맥으로 먼저 찍는다**.
    - ①탭 개별 출고장 줄 클릭 = ②품목 탭 드릴다운(`ohDrill` — 그 출고장만 펼치고 나머지 접음). '차이'가 어느 품목 탓인지 한 클릭에 보라고.
- **★대사키 = 발주일자(DLV_DT) + 출고장 + 품목코드** (2026-07-22 사용자 확정, `_ohKey`). **행 대 행이 아니라 합계 대 합계** — 출고는 사업장이 여럿이면 자동 합산된다(정산서에 BIZ 칸이 없으니 이게 정산서의 자연 단위). 출고장은 `_ohDcOf()` = DC_CD 우선, 없으면 이름 정규화. 짝 없는 출고=**미정산**, 짝 없는 정산=**출고미상**.
  - **`ORD_NO`+`ORD_ITEM_NO`를 쓰다가 갈아탐**. 옛 CLAUDE.md는 "두 표의 ORD_NO가 동일"이라 했지만, 실측 결과 **출고 쪽 ORD_NO가 절반 빈값**이라 그만큼 영영 대사 불가였다(화면에 '대사불가 573행'). 새 키는 양쪽 100% 채워져 있어 빠지는 행이 없다.
  - **실검증(2026-07-22, 20260711 두 원천이 다 있는 첫 날)**: 정산 105행→103키 / 출고 208행→115키 → **양쪽 일치 103키 = 정산서 100% 대사**. 수량까지 같은 키 102, 다른 키 1건(`평택|1000791735` 정산 6.51 vs 출고 7 = 반품 −0.49 차이로 설명됨). 출고에만 있는 12키 = **미정산 후보**. → 이 화면이 의도대로 동작함이 처음 확인됨.
- **★실측 함정 2개(2026-07-22, 운영 DB curl 확인)** — CLAUDE.md 예전 서술("두 표의 ORD_NO가 동일")은 절반만 맞았다:
  1. **출고장명 표기가 다르다**: 정산서 `평택`(파일명 유래) vs 발주현황표 `평택물류센터`. → `_ohDc()`가 공백·끝숫자·`(물류)센터`·`출고장` 꼬리를 떼어 통일. 안 떼면 같은 곳이 두 줄로 갈라진다. 라벨은 통일키, 원표기는 hover(title).
     - **DC_CD 저장 추가(2026-07-22 요청)**: 정산 엑셀에 센터코드가 없어 `DC_CD`가 NULL로 쌓이고 있었다 → 업로드 저장 시 `slsDcCd()`(JSP)가 출고장명으로 코드를 붙인다. **DTO·XML·컨트롤러는 이미 dcCd를 받고 있어 JSP만 고치면 되고 WAR 재빌드 불필요.** 업로드 목록에 `센터코드` 열이 생겨 저장 전에 확인 가능(못 찾으면 빨간 '미확인', 그래도 저장은 진행).
     - 대사 출고장키는 `_ohDcOf(r)` = **DC_CD 우선**(`_OH_CDNM` 역매핑), 없으면 이름 정규화 → 코드 저장 전후 자료가 같은 '평택'으로 수렴한다.

     - **병합셀 아님(가설 기각)**: `ORD_NO`와 `ORD_ITEM_NO`가 **함께** 비고 `JUMUN_NO`는 행마다 다른 값으로 100% 차 있다 → 파서 버그 아니고 원본이 그렇다. `ORD_GB`(전부 '1차주문')·`PROD_KIND`(전부 'TC')로도 안 갈린다 = **규칙 없음**.
- **★대사 단위: 정산서 1 : 출고 N** (2026-07-22 실측). 정산서 = **발주** 단위(105행 = 발주번호+항번 105키, 1:1) / 출고 = **발주 × 사업장** 단위(발주번호 있는 572행 = 352키). 발주 1건이 여러 점포로 쪼개져 나가기 때문.
  - **★사업장별 정산금액은 만들지 않는다(사용자 확정)**. 정산서에 BIZ 칸이 없어 사업장으로 쪼개면 어떤 방식이든 추정이 된다(비율배분도 마찬가지). ③탭은 **출고수량 전용**, 금액은 ①②(출고장·품목 단위)에서만. ③의 「정산 대사」열은 그 행의 발주번호가 정산서에 있느냐는 **사실**만 표시.
