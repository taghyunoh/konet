# konet_web 프로젝트 메모

## 스택/구조
- **MSSQL** + egovframework + MyBatis, 패키지 `egovframework.sejong`
- 뷰: Apache Tiles. `.raw/*` = tiles 래핑 없는 단독 페이지, `.main/*` = 표준 레이아웃(main.jsp+top.jsp, top.jsp는 사실상 비어있음 — 실제 네비 없음)
- **물류관리 화면은 `.raw/main/admin/logistics_demo2.jsp`(약 3000줄) 단독 셸** — 좌측 사이드바 + 모든 패널 + JS를 한 파일에 내장. 대시보드1(출고현황표)=`logistics_demo1.jsp`(iframe 로드). 사이드바 메뉴 onclick이 demo2 내부 함수/패널에 강결합 → 리팩터링 시 주의.
- 컨벤션: PK `XXX_SEQ IDENTITY`, 품목연결 `PROD_SEQ`+`PROD_CD`, 금액 `DECIMAL(18,2)`, 일자 `NVARCHAR(8)'YYYYMMDD'`·일시 `NVARCHAR(19)`, 소프트삭제 `ACTION_YN`, 감사컬럼 `REG_/UPD_`. 날짜 저장 시 `REPLACE(...,'-','')`. XML `<=`/`<` 는 CDATA 필수.

## 다중회사(멀티테넌트) — 업무 테이블 COMP_CD (2026-07-30)
**로그인(COMP_CD+USER_ID)의 회사코드로 모든 업무 데이터를 회사별 분리.** 기존 데이터는 전부 코네트(`W1234567`) 귀속.
- **DB (적용 완료·재실행 안전)**: [sql/comp_cd_multitenant_alter.sql](sql/comp_cd_multitenant_alter.sql) — 업무 테이블 **19개**에 `COMP_CD VARCHAR(10) NOT NULL DEFAULT 'W1234567' WITH VALUES`(기존행 자동 백필). **DEFAULT 제약은 지우지 말 것** — COMP_CD를 안 넣는 구버전 코드가 돌아도 기본회사로 들어가는 안전망. 업무키 확장: PK에 COMP_CD 포함(BIZI/VENDOR/SETTLE_CLOSE), UNIQUE에 포함(CLOSING_MST·PAYMENT·RECEIVE·PURCHASE UX_PURCH_NO·SETTLE_TRX UX). IDENTITY(…_SEQ) PK와 `TBL_CODE_MST/DTL`(회사 공유 공통코드)은 제외.
- **주입은 중앙 1곳 — 컨트롤러는 안 고쳤다**: `CompCdFilter`(web.xml `*.do`, 세션 `s_comp_cd`→ThreadLocal) → `CompCdContext` → **`CompCdMybatisInterceptor`**(sql-mapper-config.xml plugins) 가 모든 SQL 실행 직전 파라미터에 compCd 자동 주입. DTO는 비었을 때만 채움(로그인 폼 입력 존중) · Map은 `compCd` 키 주입 · **파라미터 없는 구문(null)은 compCd만 담은 Map으로 대체**(selectBiziMst 등 5건이 이 경로) · compCd 없는 DTO(공통코드)는 조용히 통과. **새 화면을 추가해도 주입 누락이 없다** — 엔드포인트별 dto.setCompCd(...) 방식 쓰지 말 것.
- **User_SQL.xml 123개 구문 전부 COMP_CD 반영**: SELECT/UPDATE/DELETE는 기존 관용구와 같은 **fail-open** `AND ( ISNULL(#{compCd,jdbcType=VARCHAR},'') = '' OR 별칭.COMP_CD = #{compCd...} )`(미주입=기존 동작 → 화면 안 깨짐). INSERT/MERGE ON은 **확정값** `ISNULL(#{compCd...},'W1234567')`(NOT NULL이라 명시 NULL 불가). 조인·서브쿼리·OUTER APPLY 안의 업무 테이블은 파라미터가 아니라 **본체와 COMP_CD 상관조건**(`p2.COMP_CD = p.COMP_CD` 등). 윈도우 파티션 2곳(firstDttm·keyQty/keyRows)에도 COMP_CD 추가.
- **[함정] 단일 String 파라미터 매퍼 메서드는 `@Param` 필수** — `isClosedYm`/`deleteClosingStock`은 `@Param("closeYm")`을 붙여 ParamMap이 되게 했다(안 붙이면 `#{compCd}`가 closeYm 값으로 바인딩되어 조회 0건/삭제 0건). 앞으로 업무 테이블을 만지는 새 매퍼 메서드도 단일 원시타입이면 반드시 @Param.
- **DTO 20개에 compCd 필드 추가**(Bizi/Closing(Mst)/Payment/Prod(Inprice·Saleprice)/Purchase(Dtl)/Receive/Sales(Trx·TrxDtl)/SettleClose/SettleTrx/Shipout/StockClosing/StockLedger/StockMst/Vendor). 새 업무 DTO에도 compCd 넣을 것(없으면 인터셉터가 조용히 통과 → fail-open이라 단일회사에선 티 안 남).
- **2번째 회사 등록 시**: TBL_COMP_MST/TBL_USER_MST에 회사·사용자만 넣으면 됨(compcd.jsp). 공통코드는 공유. 상품/거래처/사업장은 회사별로 새로 등록해야 함(PROD_CD 등 자연키는 회사별 독립).
- **배포**: 자바+XML+web.xml 변경 → **WAR 재빌드 필수** (빌드 확인 완료).

## 매출내역 = 정산서 업로드 + 출고 대사 (매입·재고관리 ▸ 매출내역) — TBL_SALES_MST × TBL_SHIPOUT_MST
**★성격 정정(2026-07-22, 사용자)**: 이 엑셀은 견적이 아니라 **정산서**다 — 출고장에 들어간 물품에 대해 **얼마를 받을지** 확정한 문서. 그래서 화면을 **견적서관리 ▸ 매출 엑셀 업로드 → 매입·재고관리 ▸ 매출내역**(입고내역 바로 밑)으로 옮겼다. 견적서관리 서브메뉴에서 '매출 엑셀 업로드'는 삭제.
- 메뉴명은 같은 날 **출고내역 → 매출내역**으로 한 번 더 바뀜(사용자). 화면 성격이 '출고 목록'이 아니라 '받을 금액'이라서.
- **내부 식별자는 `outHist` 그대로**(패널 `panel-outHist`, 함수 `oh*`) — 라벨만 바뀐 것이니 코드에서 `outHist`를 찾으면 이 화면이다. 사이드바에 남아있는 데모 패널 `panel-outboundList`('출고내역 / 거래명세서')와 혼동 금지(도달 불가·무관).
- **화면 4탭**(모두 JSP 내장 JS. 서버 무변경 — 기존 조회 API 2개를 합칠 뿐). **집계 2 × 원본 2 가 아니라 축 3 + 원본 1** 로 정리됨(2026-07-22, ②와 ④가 겹쳐 보인다는 사용자 지적 → ④를 사업장축으로 전환):
  ① **출고장별 합계** = 출고건수·출고수량(SHIPOUT) ↔ 정산행수·정산수량·평균단가·**정산금액(받을 금액)** + 수량차이·상태뱃지
    - **★상태는 수량차이만으로 판정하지 않는다(2026-07-22 보완)**: `정산에만 5개 + 출고에만 5개` 면 수량합 차이가 0이라 종전 로직이 **'일치'로 오진**했다. `_ohRoll`이 출고장별 대사키 집합(`sKeys`/`oKeys`)을 들고 **짝 없는 키 수**(`oOnly`=미정산 / `sOnly`=출고미상)를 세어, 하나라도 있으면 '일치'로 부르지 않고 뱃지 옆에 건수를 띄운다. 요약줄에도 총건수 표기. (합성 케이스로 오진→감지 확인)
  ② **출고장 ▸ 품목** = 품목축. 어느 품목이 어긋났나. 그룹 접기/펼치기 + 소계
  ③ **출고장 ▸ 사업장** = 사업장축, **출고수량 전용(금액 없음)**. 사업장 줄을 펼치면 출고 원본행. 하위는 기본 접힘(`_ohIsCol2(k,true)`), 접기키 접두사 `s:`/`b:` 로 ②(`i:`)와 분리. 맨 오른쪽 「정산 대사」는 **대사됨/미정산/대사불가** 상태만(배분 아님·사실)
  ④ **정산서 원본(엑셀)** = 정산서 행 그대로 + 출고수량 열. **출고장별 묶음 + 접기/펼치기 + 소계**(2026-07-22, 접기키 `t:`). ★소계의 출고수량은 **대사키 distinct 합** — 같은 (발주일자·출고장·품목) 정산행이 2개면 두 행 모두 같은 출고합계를 표시하므로 그냥 더하면 이중계상된다(`used` 가드)
- **출고장 코드↔이름 매핑은 `KONET_DC` 한 곳**(2026-07-22 통합). 종전에는 `SLS_DCCD`(이름→코드)·`_OH_CDNM`(코드→이름)·정규화 로직이 **따로 3벌**이라 한쪽만 고치면 조용히 어긋났다. 이제 `KONET_DC`(코드→이름) 하나만 고치면 역맵(`KONET_DC_R`)은 자동 생성. 공개 함수 = `konetDcShort`(표기 통일) / `konetDcCd`(이름→코드) / `konetDcNmOf`(행→지역명, DC_CD 우선). `slsDcCd`·`_ohDc`·`_ohDcOf` 는 호출부 유지용 얇은 별칭. **대시보드·매출마감의 오산센터 묶음(`CLOSE_DCGROUP`/`SS_DCGROUP`)은 성격이 다른 표라 합치지 않음**(그 둘끼리는 여전히 중복 — 별건)
  - 한쪽 원천이 통째로 없으면 빈 표 대신 **왜 비었는지 안내**(`_ohEmptyRow`) — 정산서만 없는 날/발주현황표만 없는 날을 구분해 문구가 달라진다.
  - **★출고장 묶음 = 4탭 공통 2단 트리**(2026-07-22 — 처음 '개별만' → "묶고 한 단계 더" → "매출내역 전체 공통"). 1단 = 대시보드 묶음(`CLOSE_DCGROUP` 오산센터 = 왜관·김해·광주·제주·오산, 매출마감과 동일 규칙) / 2단 = 개별 출고장(**돈의 기준** — 정산서·거래처가 출고장별이므로 여기 금액이 정산 대조 단위).
    - 공용 함수 `_ohDcGrp(지역명)` = `CLOSE_DCGROUP[KONET_DC_R[지역명]]` — 기존 매핑 재사용, 새 표 안 만듦.
    - **묶음이 2곳 이상일 때만 머리행**을 만든다(용인·평택은 혼자라 그냥 한 줄). 접기키 `d:`①/`d2:`②/`d3:`③/`d4:`④ — 탭마다 독립, **기본 펼침**(`ohGrp` 의 `/^d\d*:/` 분기가 `_ohAllCol` 을 타지 않게 막는다).

### 발주현황표(출고) — 업로드 오류내역
종전에는 양식이 다르면 **"형식이 맞지 않는 자료입니다" 한 줄**만 떠서 *어디가 다른지*를 알 수 없었다 → **오류내역 목록**을 붙였다. **저장은 막지 않는다**(막으면 정상 자료 대부분이 함께 걸림) — 알리기만 한다.
- **두 갈래로 나눠 본다**: ① **양식 대조** = 기대 컬럼 중 뭐가 없나 + *이 파일엔 실제로 뭐가 있나*(찾은 머리글 나열, 최대 25개). ② **행 대조** = 양식은 맞는데 값이 빠져 집계가 어긋날 행.
- **`lv:'e'`(빨강) = 저장·집계가 어긋남 / `lv:'w'`(노랑) = 알고만 있으면 됨.** 오류가 하나라도 'e'면 상자가 빨강. 행번호는 **엑셀 기준(r+1)** 으로 "12, 13 … 외 20행" 형태(`ssLnList`).
- **공용 자산**(정산 쪽이 그대로 재사용): CSS `.ss-pverr`(+`.warn`/`.bad`/`.ok`/`.dim`/`.ln`) · `ssHdrCells()`(앞 8~10행에서 머리글 후보 수집) · `ssLnList()`.
- **발주현황표(출고)**: `SS_FMT_SPEC`(konet/old 두 양식 스펙) → `ssFmtDiag`(맞은 개수 많은 쪽을 '가장 가까운 양식'으로) → `ssFmtErrHtml`. 행 검사는 `ssRowDiag`(출고장·수량·품목코드·사업장·납기일자) → `ssRowErrHtml`, 미리보기 표에 **빨간 행**(`tr.badrow`) 동시 표시. 표시 영역 = `#ssPvErr`.
  - **★`ssRowDiag` 의 데이터 시작행은 `ssBuildRows` 와 반드시 같아야 한다** — 둘 다 `m.dataRow!=null ? m.dataRow : m.h+2`. 한쪽만 고치면 헤더행이 '오류 행'으로 잡힌다.
  - **★양식 대조는 부분일치(`ssHdrCells().has`)** — 실제 파서 `findIn` 이 부분일치라서. 완전일치로 보면 `수량(EA)` 같은 머리글을 "없는 컬럼"이라고 잘못 적는다. **반대로 정산 쪽 파서 `eq` 는 완전일치**라 거기선 `hd.set[n]`(완전일치)을 쓴다 — 섞지 말 것.
- **★정산 엑셀(매출내역)은 오류내역 목록을 쓰지 않는다 — 대신 오류 행을 저장하지 않는다 (2026-07-26 사용자 확정, 같은 날 두 번 왕복)**
  - 경위: 처음엔 발주현황표와 같은 오류내역 목록(`slsErrHtml`/`SLS_REQ`/`SLS_OPT`/`E.*`)을 붙였다가 **"오류메세지 너무 복잡"** → **목록 UI 전부 철거**하고 문구를 기존 한 줄로 되돌렸다. 대신 **경고만 하고 저장하던 것을 '오류 행은 저장 안 함'으로 바꿨다.** 다시 오류내역 목록 얘기가 나오면 이 이력부터 확인할 것.
  - **오류 행은 `slsBuildRows` 에서 `out` 에 아예 담지 않는다**(플래그를 달아 나중에 거르는 방식 아님). 그래서 **파일 목록의 행수·출고량·매출액 = 실제로 저장될 값**이 되어 화면과 저장이 어긋날 여지가 없다.
